## Clean-room-заявление

RICON-Reforger — новая независимая кодовая база. Она написана заново на Enforce Script для Arma Reforger.

1. **Код RICON для Arma 3 (GPL-3.0) не копировался.** Ни SQF (`addons/comms`), ни C++ (`extension/`,
   `tsplugin/`, `common/`) не перенесены в этот репозиторий — ни целиком, ни фрагментами, ни построчным
   переводом на другой язык. Старый репозиторий остаётся под GPL-3.0 и служит только справочником.

   **Известное исключение (ревью `docs/review/R-core-20261018.md`, пункт P1).** Черновик
   `RICON_FreeSpaceModel` и `RICON_LinkEvaluator` (коммит `598e4e8`) повторяет структуру и константы
   A3 `extension/src/signal_core.cpp` и `fn_signalCompute.sqf`: константу FSPL `32.44`, правило
   «чувствительность = шум + 8 дБ», сентинелы и пороги. Эти два класса будут переписаны с нуля по
   собственному документу требований и первоисточникам; до этого черновик не публикуется и не
   распространяется.
   **Переписано статически (спринт 5).** Физические типы запроса и бюджета, `RICON_FreeSpaceModel`,
   `RICON_LinkEvaluator` и новые модели шума и разборчивости написаны заново только по
   `docs/req/REQ-link-eval.md` и `docs/req/REQ-core-contracts.md`; константы A3 (`32.44`, «шум + 8»,
   сентинелы, пороги `0.85 / 0.4`) в коде отсутствуют. Finding P1 по этим классам закрывается взаимным
   code review; компиляция — отдельно, `NOT_TESTED`. Класс `RICON_LinkSnapshot` пока остаётся заготовкой
   baseline и перерабатывается отдельно по `REQ-core-contracts` §8; имена и порядок состояний
   `LOST / WEAK / DEGRADED / CLEAN` сохранены как продуктовая семантика. Черновик `598e4e8` остаётся
   в истории git как неиспользуемая версия.
2. **Что взято из A3 и в каком виде.** Только требования и дизайн, изложенные заново своими словами:
   - перечень функций и сценариев (что должна уметь платформа) — `docs/plan/PLAN_RU.md` §5a;
   - уроки прошлых ошибок R-01…R-40 — как требования к новой архитектуре;
   - семантика состояний связи `LOST / WEAK / DEGRADED / CLEAN` и численные параметры черновика
     `RICON_LinkEvaluator` (пороги разборчивости 0.85 / 0.4, половинная точка кривой SNR = 10 дБ).
     Это дизайн-параметры, а не физические константы: первоисточника в стандартах у них нет.
     Они помечены как эвристика и проверяются в ревью ядра (`docs/review/R-core-*.md`).
   - алгоритм A3 для дифракции (Epstein–Peterson) используется только как legacy-эталон для сравнения,
     не как реализация.
3. **Физические формулы — по первоисточникам.** Например, потери в свободном пространстве —
   ITU-R P.525; тепловой шум kTB — общая радиотехника; дальнейшие слои HDSP — по рекомендациям ITU-R
   (P.526, P.1546, P.1812, P.372 и др.) с цитатой первоисточника в `docs/evidence/E-web2-standards-cellular.md`.
   Сотовые процедуры (номера, SMS, сервисные запросы) — игровая абстракция по мотивам 3GPP
   TS 23.003 / 23.040 / 24.090, а не реализация стандарта.
4. **Сторонние моды.** TFAR (APL-SA), ACRE2 (GPL-3.0), Coalition-VON и Lima-Charlie (без лицензии), ACE3,
   CBA изучались только ради идей, требований и известных ошибок. Их код и ассеты не копировались.
5. **Игра и инструменты.** Обратная разработка игры и Arma Reforger Tools не проводилась: её запрещает
   EULA (`Arma Reforger Tools/Docs/License.txt`, раздел «You May Not»). Ванильные скрипты и ассеты изучаются
   только через Workbench. Ванильные файлы игры в репозиторий не включаются.

6. **Производная работа NTIA/ITS (общественное достояние США).** `oracle/ground_wave_oracle.py` — перенос на
   Python программы NTIA/ITS LFMF v1.1 (https://github.com/NTIA/LFMF), созданной сотрудниками NTIA и не охраняемой
   авторским правом в США (15 U.S.C. 105); `LICENSE.md` NTIA разрешает производные работы с пометкой изменений.
   Изменения claude от 2026-10-24 перечислены в шапке файла. `oracle/data/lfmf_examples_ntia_v1.csv` — точная копия
   тестовых данных NTIA/LFMF-test-data (`LFMF_Examples.csv`), используется только как тестовые данные. Благодарность
   NTIA/ITS. Это эталон host-проверки, не код мода; в Enforce-аддон он не входит.
