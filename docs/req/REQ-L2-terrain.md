## Мини-intent

- **Проблема:** L0 считает только свободное пространство: холм между рациями ничего не меняет.
- **Результат:** детерминированная функция потерь дифракции по профилю рельефа по P.526-16 §4.5
  (ур. 66), её закрытые отказы и адаптер к seam `RICON_PropagationModel`; независимый host-эталон.
- **Затронуто:** новая модель распространения (Enforce, R19, codex), поставщик профиля, `oracle/` (claude).
- **Ограничения:**
  - clean-room;
  - без калибровки по игре;
  - **здания, деревья и материалы — не L2**: это отдельный будущий слой. Оговорка стандарта про clutter (§4.5)
    в L2 не применяется;
  - игру не запускать.
- **Открыто:**
  - шаг сетки высот Reforger и стоимость `GetSurfaceY` (runtime);
  - соответствует ли результат «ощущению» в игре — опыты Э1r;
  - нужен ли отдельный код причины в `RICON_EReason` (вопрос к REQ-core, §8).

## 2. Вход чистой функции `L2(input, config)`

**Профиль** — `n` пар `(d_i, h_i)`, `i = 1..n` (§4.5, пересказ: первая и последняя точки — земля под антеннами,
высоты антенн задаются отдельно, интерполяции между точками нет).

- `n ≥ 3`;
- `d_1 = 0`, строго возрастает, `d_n = d`, `0 < d ≤ 500` км;
- все значения конечные, высоты `h_i` в `[−1000, 10000]` м;
- максимальный шаг: `d_i − d_{i−1} ≤ maxProfileStepKm·(1 + 10⁻⁶)` (стандарт предупреждает о больших шагах).
  Множитель — закрепление RICON: равномерный профиль с шагом ровно `maxProfileStepKm` после округления (float64
  и тем более float32) иначе отвергался бы.

**Антенны:** `htg`, `hrg` — высоты над землёй, м, конечные, в `(0, 10000]`. Тогда `h_ts = h_1 + htg`, `h_rs = h_n + hrg`.

**Частота** `f`, МГц, конечная, `30 ≤ f ≤ 100000`. Нижняя граница: §3.2 требует `f ≥ 10 МГц`, а данные §4
относятся к `f > 30 МГц`; берём более строгую. Верхней границы стандарт для §4.5 не задаёт.

**Границы домена** (`d ≤ 500` км, высоты, `f ≤ 100000` МГц) — закрепление RICON, а не стандарта. Они реалистичны
для любой карты и держат все промежуточные величины далеко от переполнения float32. Без них один и тот же вход мог
бы дать `OK` в float64 и `NUMERIC_FAILURE` в float32. Код `NUMERIC_FAILURE` остаётся защитным.

**Конфиг** (обязателен, значений по умолчанию нет — как константы P.372 в L0):

| Поле | Домен | Назначение |
|---|---|---|
| `earthRadiusKm` | > 0, конечное | средний радиус Земли `a` |
| `kFactor` | > 0, конечное | `a_e = kFactor · earthRadiusKm` |
| `permittivity` ε | > 1 (строго), конечное | §3.1.1.1; при ε = 1 и σ = 0 в (11a) получается 0^(−1/4), K бесконечен (найдено перебором oracle) |
| `conductivitySm` σ | ≥ 0, конечное | См/м |
| `polarization` | `VERTICAL` \| `HORIZONTAL` | выбор (11a) или (12a) |
| `maxProfileStepKm` | > 0, конечное | граница шага профиля |

Тестовые значения векторов (`TEST_ONLY`, не рекомендация): `a = 6371`, `k = 4/3`, ε = 15, σ = 0.001 (подпись одной
из кривых Fig. 2), `VERTICAL`. Настоящие значения для карт Reforger выбираются отдельно (нужны опыты).

## 3. Результат и закрытые коды

Результат: `code`; при `OK` ещё `L`, `Lba`, `Lbs`, `Lsph` (дБ), `branchActual` и `branchSmooth`
(`LOS` | `TRANS`), `sphCase` (§5.3).

Коды проверяются **строго в этом порядке**, первый сработавший возвращается:

| # | Код | Условие |
|---|---|---|
| 1 | `INVALID_CONFIG` | любое поле конфига вне домена §2 |
| 2 | `OUT_OF_DOMAIN_FREQUENCY` | `f` не конечна или вне `[30, 100000]` |
| 3 | `INVALID_PROFILE` | `n < 3`, `d_1 ≠ 0`, не строго возрастает, не конечное значение, `d > 500` км, высота вне `[−1000, 10000]` |
| 4 | `PROFILE_STEP_TOO_LARGE` | шаг больше `maxProfileStepKm·(1 + 10⁻⁶)` |
| 5 | `INVALID_ANTENNA_HEIGHT` | `htg` или `hrg` не конечна или вне `(0, 10000]` |
| 6 | `NUMERIC_FAILURE` | любое промежуточное значение или результат не конечны |
| 7 | `OK` | |

`L ≥ 0` при `OK` — следствие формул (J ≥ 0 при ν > −0.78, ур. 57 и 66); нарушение означает дефект и проверяется
oracle.

## 4. Bullington (§4.5.1, ур. 49–57)

Для профиля `(d_i, h_i)` и высот `h_ts`, `h_rs` (masl), с `C_e = 1/a_e` (км⁻¹). Индексы промежуточных точек —
`i = 2..n−1`; при `n ≥ 3` множество не пусто.

1. `S_tim = max_i [ (h_i + 500·C_e·d_i·(d − d_i) − h_ts) / d_i ]` (49).
2. `S_tr = (h_rs − h_ts) / d` (50).
3. **LoS**, если `S_tim < S_tr` (строго):
   `ν_max = max_i { [h_i + 500·C_e·d_i·(d − d_i) − (h_ts·(d − d_i) + h_rs·d_i)/d] · √(0.002·d / (λ·d_i·(d − d_i))) }`
   (51); `L_uc = J(ν_max)` (52).
4. **Trans-horizon**, если `S_tim ≥ S_tr`:
   - `S_rim = max_i [ (h_i + 500·C_e·d_i·(d − d_i) − h_rs) / (d − d_i) ]` (53);
   - `d_b = (h_rs − h_ts + S_rim·d) / (S_tim + S_rim)` (54);
   - `ν_b = [h_ts + S_tim·d_b − (h_ts·(d − d_b) + h_rs·d_b)/d] · √(0.002·d / (λ·d_b·(d − d_b)))` (55);
   - `L_uc = J(ν_b)` (56).
   - **Вырожденный случай (закрепление RICON):** если `S_tim + S_rim == 0` (только точное касание: вершина
     препятствия лежит на прямой между антеннами), `d_b` не определено. Тогда считается по пункту 3 (ур. 51–52):
     это та же точка с ν = 0.
   - Следствие: при `S_tim = S_tr` всегда `S_tim + S_rim = 0` — точка с наибольшим наклоном лежит на линии, а любая
     точка ниже линии даёт `S_rim < −S_tr`. Поэтому «строго `<`» в п. 3 и «`≤`» дают один результат; oracle
     проверяет это тестом, а не вектором.
5. `J(ν) = 6.9 + 20·log(√((ν − 0.1)² + 1) + ν − 0.1)` (31) при `ν > −0.78` (строго), иначе `J = 0`.
   Примечание: в тексте (52) стандарт пишет «ν_b», по смыслу это `ν_max`; порог тот же.
6. `L_b = L_uc + [1 − exp(−L_uc/6)]·(10 + 0.02·d)` (57).

`branch` — какая ветка выбрана в п. 3/4 (вырожденный случай даёт `LOS`).

## 5. Полный метод (§4.5.2, ур. 58–66)

### 5.1 Реальный профиль

`Lba = L_b` (§4 этого документа) для реального профиля, `h_ts`, `h_rs`; `branchActual` — его ветка.

### 5.2 Гладкая поверхность и модифицированные высоты

1. `v1 = Σ_{i=2..n} (d_i − d_{i−1})·(h_i + h_{i−1})` (58).
2. `v2 = Σ_{i=2..n} (d_i − d_{i−1})·[h_i·(2d_i + d_{i−1}) + h_{i−1}·(d_i + 2d_{i−1})]` (59).
3. `h_stip = (2·v1·d − v2) / d²` (60a), `h_srip = (v2 − v1·d) / d²` (60b).
4. Для `i = 2..n−1`: `h_obi = h_i − [h_ts·(d − d_i) + h_rs·d_i]/d` (61d); `h_obs = max h_obi` (61a),
   `α_obt = max(h_obi / d_i)` (61b), `α_obr = max(h_obi / (d − d_i))` (61c). Геометрия плоская, без кривизны.
5. Если `h_obs ≤ 0`: `h_stp = h_stip`, `h_srp = h_srip` (62a, 62b). Иначе `g_t = α_obt/(α_obt + α_obr)`,
   `g_r = α_obr/(α_obt + α_obr)` (62e, 62f), `h_stp = h_stip − h_obs·g_t`, `h_srp = h_srip − h_obs·g_r` (62c, 62d).
   При `h_obs > 0` оба угла положительны (в точке максимума `h_obi > 0`), знаменатель не нулевой.
6. `h_st = min(h_stp, h_1)`, `h_sr = min(h_srp, h_n)` (63a–63d: «если больше — взять высоту земли»).
7. `h'_ts = h_ts − h_st`, `h'_rs = h_rs − h_sr` (64a, 64b). Так как `h_st ≤ h_1`, `h'_ts ≥ htg > 0`; так же
   `h'_rs > 0`.

`Lbs = L_b` (§4) для **того же набора `d_i`, но все `h_i = 0`**, с высотами `h'_ts`, `h'_rs`; `branchSmooth` —
его ветка.

### 5.3 Сферическая Земля (§3.2, ур. 21–25, затем §3.1.1)

Входы: `d` (путь), `h1 = h'_ts`, `h2 = h'_rs` (65a, 65b), `λ`, `a_e`. В (21)–(24) всё в метрах.

1. `d_los = √(2a_e)·(√h1 + √h2)` (21). Если `d ≥ d_los`: `Lsph = A_beyond = −(F(X) + G(Y1) + G(Y2))`
   по §3.1.1 с `a_e`; `sphCase = BEYOND`. Значение не ограничивается снизу (ограничение даёт (66)).
2. Иначе: `m = d²/(4a_e·(h1 + h2))` (22e), `c = (h1 − h2)/(h1 + h2)` (22d),
   `b = 2·√((m + 1)/(3m))·cos(π/3 + (1/3)·arccos((3c/2)·√(3m/(m + 1)³)))` (22c). Аргумент `arccos` ограничивается
   отрезком `[−1, 1]` (закрепление RICON: защита от округления, математически он уже там).
   `d1 = (d/2)·(1 + b)` (22a), `d2 = d − d1` (22b),
   `h = [(h1 − d1²/(2a_e))·d2 + (h2 − d2²/(2a_e))·d1] / d` (22),
   `h_req = 0.552·√(d1·d2·λ/d)` (23).
3. Если `h > h_req`: `Lsph = 0`, `sphCase = CLEAR`.
4. Иначе: `a_em = 0.5·(d/(√h1 + √h2))²` (24); `A_h = −(F(X) + G(Y1) + G(Y2))` по §3.1.1 с `a_em` **вместо `a_e`
   во всех формулах §3.1.1, включая K** (стандарт: «modified effective earth radius … in place of»).
   Если `A_h < 0`: `Lsph = 0`, `sphCase = AH_NEGATIVE`. Иначе `Lsph = (1 − h/h_req)·A_h` (25),
   `sphCase = INTERPOLATED`.

**§3.1.1 — нормативно в практических единицах** (`d` км, `a` км — то есть `a_e` или `a_em`, `h` м, `f` МГц).
Стандарт даёт и форму в согласованных единицах (11), (12), (14), (15), но практические формы округляют
константы (например, 0.36 против точных ≈ 0.3627 в (11a)). Независимый расчёт claude показал расхождение двух форм
до **0.13 дБ** в `Lsph`: вертикальная поляризация, 50 МГц, антенны 2 м, где G упирается в клэмп `2 + 20·log K`.
Это больше допуска parity, поэтому закреплена одна форма — практическая.

- `K_H = 0.36·(a·f)^(−1/3)·[(ε − 1)² + (18000·σ/f)²]^(−1/4)` (11a); `K_V = K_H·[ε² + (18000·σ/f)²]^(1/2)` (12a);
  `K` — по `config.polarization`.
- `β = (1 + 1.6K² + 0.67K⁴)/(1 + 4.5K² + 1.53K⁴)` (16). **Закрепление RICON:** β всегда вычисляется по (16).
  Стандарт разрешает β = 1 в части случаев («may be taken») — это приближение, и две реализации разошлись бы.
- `X = 2.188·β·f^(1/3)·a^(−2/3)·d` (14a); `Y = 9.575·10⁻³·β·f^(2/3)·a^(−1/3)·h` (15a); `B = β·Y` (18b).
- `F(X) = 11 + 10·log X − 17.6·X` при `X ≥ 1.6` (17a), иначе `F(X) = −20·log X − 5.6488·X^1.425` (17b).
- `G(Y) = 17.6·(B − 1.1)^(1/2) − 5·log(B − 1.1) − 8` при `B > 2` (18), иначе `G(Y) = 20·log(B + 0.1·B³)` (18a);
  затем, если `G < 2 + 20·log K`, `G = 2 + 20·log K`.
- Условие точности (19) стандарт приводит как оценку «лучше 2 дБ»; **в расчёт оно не входит** (только
  информация, решения не меняет).

### 5.4 Итог

`L = Lba + max(Lsph − Lbs, 0)` (66).

**Находка о гладком пути.** Стандарт (§4.5, пересказ) говорит, что для полностью гладкого пути результат совпадает
со сферической моделью. Из (66) точно следует только: при гладком профиле `Lba = Lbs`, поэтому `L = max(Lsph, Lbs)`.
Совпадение со сферической моделью есть, лишь когда `Lsph ≥ Lbs`. Вектор S06 (морская поверхность, 30 МГц,
антенны 3 м) даёт `A_h < 0`, то есть `Lsph = 0`, а `L = Lbs ≈ 12.3 дБ`. Реализация следует формулам, а не этой
фразе стандарта.

## 6. Адаптер к seam модели (Enforce, R19)

- Новая модель `RICON_TerrainDiffractionModel : RICON_PropagationModel`, `GetModelId()` — стабильный id. Она
  добавляет **два** слоя: свободное пространство (тем же расчётом L0, `RICON_FreeSpaceModel.LossDb`) и
  `terrain_diffraction` = `L`. Так evaluator с одной моделью на диапазон получает полный бюджет.
- `IsConfigValid()` = конфиг §2 валиден и поставщик профиля задан. `IsApplicable(f)` = `f ≥ 30` и конечна.
- Профиль даёт seam `RICON_TerrainProfileProvider` (без engine-кода в модели):
  - вход — горизонтальные координаты концов (`x`, `z` позиций запроса, м);
  - выход — `n = max(3, ceil(d/step) + 1)` равноотстоящих точек с `d_i` (км) и высотами земли `h_i` (м);
  - `d` — **горизонтальное** расстояние между концами;
  - высоты антенн над землёй `htg = tx.y − h_1`, `hrg = rx.y − h_n`.

  Реализация для игры (`BaseWorld.GetSurfaceY`, `DOC`) — runtime, `BLOCKED_NO_RUNTIME`; для parity — synthetic
  provider с профилем из векторов.
- Горизонтальное `d == 0` (один столб) — профиль не строится, слой `terrain_diffraction` = 0.
- Любой код, кроме `OK`, → `AppendLosses` возвращает `false`, evaluator выдаёт существующий `NUMERIC_FAILURE`
  (REQ-LE) плюс диагностику с кодом L2. Отдельная причина в `RICON_EReason` — вопрос §8.
- Числа: float32 в Enforce. Допуск parity против host float64 — **0.05 дБ** по `L`, `Lba`, `Lbs`, `Lsph`; ветки
  и `sphCase` — точное совпадение. PLAN §Э4 DoD разрешает ±0.5 дБ на слой, 0.05 дБ строже и подходит чистой
  математике. Если float32 не уложится, это находка, а не повод тихо расширить допуск.
- **Запас до ветвлений.** Векторы для parity не ставятся ближе `10⁻³` (относительно) к порогам ветвлений:
  `S_tim = S_tr`, `S_tim + S_rim = 0`, `ν = −0.78`, `X = 1.6`, `B = 2`, `h_obs = 0`, `h = h_req`, `d = d_los`,
  `A_h = 0`. Ближе float32 и float64 законно выбирают разные ветки. Точные границы проверяются host-тестами
  oracle, а не parity.
