# P2 — наблюдение пути и водный слой

Версия **0.1 DRAFT**, 2026-10-22. Автор claude, независимая проверка codex. Источник истины — этот репозиторий.
Основание: утверждённый владельцем план P1–P5 (чат, «Приступайте к реализации плана»; agora #3307–#3325, #3311),
роли P2 — REQ и эталон claude, код codex (#3308). Первоисточник воды — Rec. ITU-R P.527-6 (09/2021), локальная
копия `STD_COPY`, SHA-256 DOCX `cbb067b9…c1db27f` (как в `E-web6-p527-ground.md`); текст стандарта в репозиторий не
переносится, ниже — номера уравнений и пересказ. Корпус до независимого пересчёта — DRAFT, Enforce до freeze не пишется.

## 1. Назначение и границы

**PO01.** P2 вводит общий контракт «что лежит на пути TX→RX» для пяти семейств: рельеф, вода, постройки,
растительность, техника — и первую модель потерь — водный слой. Постройки (P3), растительность (P4) и техника (P5)
здесь получают только форму наблюдения и правила проверки, не потери. Наблюдения из мира (трассы, `GetSurfaceY`,
поверхность воды) в P2 не исполняются: эталон и native-код работают с синтетическими наблюдениями.

**PO02.** Наблюдение отделяет геометрию от знания о RF-материале. Неизвестное явно помечается `UNKNOWN` с причиной;
оно не превращается ни в воздух (0 дБ), ни в обрыв (LOST). Неполное покрытие семейства — `UNRESOLVED` для
зависящих от него слоёв, а не «препятствий нет». Решение о доставке, LinkEvaluator, S3/S3b и снимки не меняются.

## 2. Контракт наблюдения пути

**PO03. Вход `PathObservation`.**

| Поле | Домен и смысл |
|---|---|
| frequencyMHz | конечное > 0; частота, для которой собрано наблюдение |
| environmentRevision | int 1..MAX; версия условий среды, которой соответствует наблюдение |
| tx, rx | `Endpoint` (PO05) |
| coverage | по одному значению на семейство TERRAIN, WATER, STRUCTURE, VEGETATION, VEHICLE: `COMPLETE`, `PARTIAL` или `NOT_OBSERVED` |
| segments | список ≤ 1024 записей `Segment` (PO04) |

Расстояние L = |rx.position − tx.position| (м) обязано быть > 0. MAX = 2147483647. Каждое число входа — конечное и
по модулю не больше наибольшего binary32 (3.4028234663852886e38); эталон считает в binary64 по десятичным значениям
JSON, native — во float32. bool и строки не числа; лишние поля JSON запрещены.

**PO04. `Segment` — участок прямой TX→RX, занятый объектом одного семейства.**

| Поле | Домен и смысл |
|---|---|
| family | WATER, STRUCTURE, VEGETATION или VEHICLE (рельеф описывает профиль L2, PO06) |
| startM, endM | 0 ≤ startM < endM ≤ L, вдоль прямой от TX |
| entityKey | непустая строка ≤ 64 символа; стабильный ключ объекта в пределах environmentRevision |
| knowledge | `PROFILE` (RF-профиль компонента или материала), `RULE` (проверенное правило префаба/класса), `HINT_ONLY` (только подсказка, например BallisticInfo), `UNKNOWN` |
| materialId | непустой id каталога RICON при PROFILE/RULE; пустой при HINT_ONLY/UNKNOWN |
| openings | bool; известны проёмы (окно, дверь), через которые может пройти часть энергии |

Сегменты упорядочены по (startM, family, entityKey). Пересечение сегментов **одного** entityKey запрещено; сегменты
разных объектов и семейств могут перекрываться (дерево у стены). Составной модовый объект — несколько сегментов с
одним entityKey без перекрытия.

**PO05. `Endpoint` — антенна одного конца.**

| Поле | Домен и смысл |
|---|---|
| position | вектор (м), мировая система |
| medium | `AIR`, `WATER` или `UNKNOWN` |
| depthM | при WATER: конечное ≥ 0, глубина антенны под локальной поверхностью воды; иначе 0 |
| waterClass | при WATER: `SEA`, `FRESH` или `UNKNOWN`; иначе `NONE` |
| waterBodyKey | при WATER: ключ водоёма или пустая строка, если водоём не опознан |

Сегменты WATER в v0.1 только описательные: водный слой (§3) считает потери по концам (PO05), потому что прямая
между двумя точками над плоской поверхностью воды под воду не уходит.

**PO06.** Рельеф описывается существующим профилем L2/S1 и в сегменты не входит, чтобы не учитывать его дважды.
coverage.TERRAIN фиксирует, получен ли профиль.

**PO07. Проверка наблюдения.** Порядок отказов: `INVALID_OBSERVATION` (структура, домен, порядок, перекрытие
одного объекта, materialId вопреки knowledge, поля Endpoint вопреки medium) → `VALID`. Проверка глобальная.

**PO08. Источники движка (DOC_ONLY, в P2 не исполняются).** Высоты — `GetSurfaceY` (S1). Вода —
`ChimeraWorldUtils.TryGetWaterSurface(world, point, out surfacePoint, out EWaterSurfaceType, …)` и
`TryGetWaterSurfaceSimple` (Script API Public, установленная документация); значения `EWaterSurfaceType` в документации
не перечислены, соответствие типу воды RICON — отдельная проверка в Workbench. Постройки и техника — трассы мира и
тип сущности; материал — `GameMaterial`/`BallisticInfo` только как подсказка (`E-workbench-source.md:240–252`).

## 3. Водный слой `water_p527`

**WL01. Среда.** Комплексная относительная проницаемость воды εw = ε′ − jε″ по P.527-6 §5.1.2, ур. (14)–(27), от
частоты f (ГГц), температуры T (°C) и солёности S (‰): релаксационная модель с двумя частотами Дебая f1s, f2s,
параметрами εss, ε1s, ε∞s (ур. 17–21, основа — ур. 8–13 чистой воды) и членом проводимости 18·σsw/f в ε″ (ур. 16);
σsw = σ35·R15·RT15 (ур. 22–27). Чистая вода — частный случай S = 0 (ур. 5–7). Область: −4 ≤ T ≤ 40 °C,
0 ≤ S ≤ 40 ‰ (§5.1), f ≤ 1000 ГГц (Annex 1). Вне области — `OUT_OF_MODEL_DOMAIN`.

**WL02. Профиль воды.** Класс SEA и FRESH задаёт профиль RICON: T и S для каждого класса. Пресная вода считается
по тем же ур. (14)–(27) с малой солёностью: при S = 0 проводимость равна нулю, а природная пресная вода проводит
ток. Значения T и S профиля — **TEST_ONLY** до решения владельца или калибровки; производственных чисел по
умолчанию нет. Класс `UNKNOWN` или отсутствие профиля — `WATER_CLASS_UNKNOWN`.

**WL03. Затухание в воде.** n = √εw — главный корень, Im n ≤ 0. Погонные потери
αdB = 20·log10(e)·(2π/λ)·|Im n| дБ/м, λ = c/f, c = 299 792 458 м/с. Это то же затухание, что глубина
проникновения P.527-6 ур. (4): αdB = 20·log10(e)/δ.

**WL04. Граница воздух–вода.** Нормальное падение: Γ = (1 − n)/(1 + n), потери прохождения
Lint = −10·log10(1 − |Γ|²) дБ. Это оценка, не строгая нижняя граница: при наклонном падении с воздуха отражение
TM-волны около псевдо-угла Брюстера бывает меньше, чем при нормальном. Поэтому в v0.1 водный слой **не** выдаёт
строгих границ для P1 (P1 при наличии воды получает MISSING_PATH_BOUND).

**WL05. Конвенция RICON «выход по вертикали».** Сигнал погружённой антенны выходит к поверхности над ней:
потери конца Lend = depthM·αdB + Lint. Обоснование: при |n| ≫ 1 преломлённый в воде луч почти нормален к
поверхности при любом угле в воздухе. Для воздушной части других слоёв эффективная точка антенны —
(x, ySurface, z), где ySurface = y + depthM. Конвенция не моделирует волну вдоль поверхности и отражение от дна.

**WL06. Оба конца в одном опознанном водоёме** (оба WATER, одинаковый непустой waterBodyKey): дополнительно
считается прямой подводный путь Ldirect = L·αdB, где L — расстояние между антеннами. Итог —
min(Ldirect, LendTX + LendRX), выбранный вариант указывается. При разных или неопознанных водоёмах — только выход по
вертикали.

**WL07. Результат.** Порядок причин: `INVALID_OBSERVATION` (PO07) → `INVALID_PROFILE` (профиль: только ключи SEA и
FRESH, у каждого ровно tempC и salinityPpt, конечные числа) → `WATER_COVERAGE_INCOMPLETE` (coverage.WATER ≠ COMPLETE
либо medium UNKNOWN у любого конца) → `NO_SUBMERGED_ENDPOINT` (ни один конец не в воде, слой 0 дБ — вычислено, не
absent) → `WATER_CLASS_UNKNOWN` (класс UNKNOWN или нет в профиле) → `OUT_OF_MODEL_DOMAIN` (T, S профиля вне §5.1 или
f > 1000 ГГц) → `NUMERIC_FAILURE` (любое выходное число неконечно, отрицательно или больше наибольшего binary32) → `OK`. Только OK и NO_SUBMERGED_ENDPOINT дают значение
слоя `lossDb` ≥ 0; остальные — слой absent и причина для UNRESOLVED. При OK выдаются также `variant`
(`VERTICAL_EXIT` или `DIRECT_UNDERWATER`), по каждому погружённому концу αdB, Lint, Lend и эффективная точка.
Водный слой никогда не объявляет LOST сам: это решают отсечка P1 и evaluator.

## 4. Проверка и передача партнёру

**PO09.** Эталон `oracle/path_observation_oracle.py`, корпус `oracle/vectors/path_observation_v1.json`:
проверка наблюдения (все отказы PO07, порядок, перекрытия, составной объект) и водный слой (пресная и морская
вода, мелкая и глубокая антенна, граница области T/S, неизвестный класс, неполное покрытие, оба конца в одном и в
разных водоёмах, выбор DIRECT_UNDERWATER). Сверка ε с рисунками P.527-6 Fig. 2 (T = 20 °C) — отдельный unit-тест с
допуском чтения графика, и с глубиной проникновения Fig. 1; σsw морской воды 35 ‰ при 20 °C ≈ 4.79 См/м.
Native сравнивает коды и variant строго, числа — с допуском max(1e-3 дБ, 1e-5·|x|) (float32 и комплексный корень
против binary64); корпус не содержит случаев, где выбор variant ближе этого допуска.

Корпус v1 DRAFT: 42 случая (O01–O20 наблюдение, W01–W22 водный слой), LF SHA-256 `6b5c99c753d1780bbf426433abe8fe86ddafea598d2113ccf2a0e0b9b88171de`; собирается
`oracle/build_path_observation_vectors.py` (ожидания — из эталона). Ошибки JSON-типа O16 (лишнее поле) и O19 (bool
вместо числа) недостижимы в типизированном Enforce и остаются host-only; остальные 40 — для native.
Команды: `python oracle/path_observation_oracle.py --check oracle/vectors/path_observation_v1.json`;
`python -m unittest discover -s oracle -p test_path_observation_oracle.py`.

Сначала codex проверяет REQ, затем пересчитывает корпус своим checker по REQ, не читая эталон. После согласия —
freeze по LF SHA, затем Enforce codex, ревью и повторный прогон claude. Игровая приёмка, реальные наблюдения мира,
соответствие `EWaterSurfaceType` и слышимость — NOT_RUN.
