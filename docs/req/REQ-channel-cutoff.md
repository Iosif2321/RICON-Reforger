# P1 — отсечка пренебрежимо малого полезного вклада

Версия **0.1 DRAFT**, 2026-10-22. Автор codex, независимая проверка claude.
Источник истины — этот репозиторий. Основание: утверждённый владельцем план в чате,
Agora #3313/#3324/#3325 и поручение «Implement the plan» (#3327).
Применены Ponytail full и существующий процесс ai-native-sdlc-cycle; пользователь прямо поручил
продолжить реализацию в текущем разговоре. Новую чистую сессию не заявляем.

## 1. Назначение и границы

**CC01.** Чистая функция `Assess(input)` решает, можно ли прекратить вычисление **всего полезного
вклада одной передачи на одном участке TX→RX** на явно заданном интервале. Это не демодулятор,
шумоподавитель, модель речи или правило удаления помех. Ноль полезной линейной мощности не равен 0 дБм.
Результат не меняет `RICON_ELinkState`, LinkEvaluator, S3/S3b или snapshot v1.

**CC02.** Возможны `BOUNDED` (полезный вклад принят равным нулю с объявленной границей), `CONTINUE`
(оснований прекращать нет), `UNRESOLVED` (неполные данные/ресурс/невалидный вход). Только BOUNDED
разрешает пропустить оставшуюся цепочку полезного сигнала. Отсутствующие потери остаются absent,
не превращаются в слои с нулём; частичный бюджет не становится полным.

**CC03.** Источник границ — серверная модель, не клиент и не произвольный вход из сети. Она обязана
учесть все возможные продолжения пути, отрицательные потери, отражения и временные изменения.
Ретранслятор начинает новый участок с отдельным источником. Перцентиль/среднее не являются строгой
границей. Для стохастического хвоста без строгой границы отсечка выключена. Независимые случайные
«спасения» данных не добавляются. Временная модель P1b — отдельный обязательный этап после P2.

## 2. Вход и порядок проверок

**CC04.** Поля входа:

| Поле | Домен и смысл |
|---|---|
| nowMs, validFromMs, validUntilMs | int 0..2147483647; общий интервал доказательства `[from, until)` |
| environmentRevision, boundRevision | int 1..2147483647; версия текущих условий и версия доказательства |
| coverageComplete | bool; полный набор возможных составляющих и применимость моделей подтверждены |
| resourceExhausted | bool; не удалось завершить построение наблюдений/границ в пределах ресурса |
| toleranceDbm | конечное binary32 либо null; верхний предел отбрасываемой полезной мощности, **не порог RX** |
| numericalGuardDb | конечное binary32 ≥0 либо null; подтверждённый запас для численной ошибки агрегации |
| paths | список до 4096 записей `{pathId, upperDbm}`; уникальный непустой pathId, upperDbm — конечное binary32 либо null |

`upperDbm` — строгая верхняя граница **конечной мощности этой составляющей на входе RX**, включая
оставшуюся цепочку и весь интервал. null означает «границы нет», не нулевую мощность. Все числовые
поля приводятся к binary32 до проверки; bool/строка не число. Нечисловые специальные значения в
JSON тестов — строки NaN/+Inf/-Inf, как у S2. Все поля обязательны, кроме отсутствующего значения,
представленного null. Дополнительные поля в JSON запрещены. Вход не меняется.

**CC05.** Порядок отказов/решений: INVALID_INPUT (структура/тип/домен/повтор id/неправильный интервал)
→ RESOURCE_EXHAUSTED → INCOMPLETE_COVERAGE → STALE_BOUND (версии не равны или now вне интервала)
→ EMPTY_PATH_SET → MISSING_PATH_BOUND → NUMERIC_UNCERTIFIED → NUMERIC_FAILURE → CUTOFF_DISABLED
→ BELOW_TOLERANCE / ABOVE_TOLERANCE. INVALID_INPUT, RESOURCE_EXHAUSTED, INCOMPLETE_COVERAGE,
STALE_BOUND и NUMERIC_FAILURE дают UNRESOLVED; остальные — правила §3.
Проверки глобальные: дефект последней записи запрещает принять отсечку по первой.

## 3. Сложение и решение

**CC06.** Неизвестные фазы не разрешают складывать мощности как некогерентные. Безопасная общая
граница выводится из неравенства треугольника для амплитуд:

`U = m + 20 log10(sum(10 ** ((upperDbm_i - m) / 20))) + numericalGuardDb`, `m = max(upperDbm_i)`.

Это верхняя граница квадрата суммы амплитуд, не модель фактического сложения путей. Максимум вынесен
для устойчивости. Ни одна слабая составляющая до этой агрегации отдельно не удаляется. Допуск
применяется один раз ко всему вкладу, поэтому ошибка нескольких путей не накапливается незаметно.
Формула — математическое неравенство, не эмпирическая RF-модель. Временная изменчивость —
[ITU-R P.1407-8](https://www.itu.int/rec/R-REC-P.1407/en), не источник конкретных коэффициентов здесь.

**CC07.** При отсутствии хотя бы одной границы: CONTINUE/MISSING_PATH_BOUND, общего U нет.
При отсутствии численного запаса: CONTINUE/NUMERIC_UNCERTIFIED, общего U нет. Численный запас
задаёт проверенный численный профиль модели; производственного значения по умолчанию нет.
Нулевой запас допустим в тестовом эталоне, но не доказывает точность арифметики Enforce.
Численный сбой/выход U за конечный диапазон binary32 — UNRESOLVED/NUMERIC_FAILURE.

**CC08.** Если все границы получены: при toleranceDbm=null — CONTINUE/CUTOFF_DISABLED с U;
если `U < toleranceDbm` — BOUNDED/BELOW_TOLERANCE; иначе CONTINUE/ABOVE_TOLERANCE.
Равенство не отсекается. Пустой **подтверждённо полный** набор путей даёт BOUNDED/EMPTY_PATH_SET:
точный ноль полезного вклада без выдуманного значения дБм. Неполный пустой набор — UNRESOLVED.

**CC09.** Результат: `decision`, `reason`, `usefulIsZero`, `upperDbm` (null при отсутствии границы).
usefulIsZero=true только при BOUNDED. У BELOW_TOLERANCE upperDbm сохраняет границу ошибки;
у EMPTY_PATH_SET upperDbm=null означает точный ноль по причине, а не неизвестность.
Результат применим только к проверенной версии среды и оставшейся части указанного интервала.
После истечения/инвалидации повторный Assess обязателен. Никакой вечной отсечки на весь PTT.

## 4. Проверка и следующий шаг

Эталон: `oracle/channel_cutoff_oracle.py`; корпус `oracle/vectors/channel_cutoff_v1.json`.
Сравнение чисел эталона с независимым checker — 1e-6 дБ, решение/причина/признаки строго.
Проверяются последующий выигрыш (включён в upperDbm), сумма слабых путей, неоднозначные фазы,
границы времени/revision, отсутствие стохастической границы, неизвестная геометрия, ресурс,
пустой набор, NaN/Inf/overflow, выключенная отсечка, неизменность входа и порча корпуса.
Проверка граничных решений Enforce не заменяется численным допуском компаратора.

Открыто: независимый пересчёт, freeze, Enforce, сертификация численного запаса и фактическая выдача
строгих границ моделями мира. До этого production-вызовы не подключаются и эффект экономии не заявляется.
Проверенный Assess не заменяет будущие наблюдения P2–P5, временную модель или игровой actuator.
