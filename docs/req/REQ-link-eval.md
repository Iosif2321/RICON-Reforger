# REQ-link-eval — требования к оценке одного радиолинка

Версия: **0.3 AGENT-REVIEWED** (взаимная проверка claude + codex, agora id481, id483), 2026-10-18, спринт 3. Это не приёмка владельцем, не runtime-проверка и не freeze Э2; `BLOCKED_CALIBRATION` и пробел по редакции P.372 остаются (тема agora `ricon-reforger-build`).
Автор: claude. Ревью: codex. Правка №1 списка `docs/review/R-core-20261018.md`.

## 0. Как читать

- Документ написан с нуля, своими словами. Код и тексты A3 при написании не использовались. Числа A3 могут
  применяться позже только для сравнения (legacy comparator), не как требование.
- Физика — по первоисточникам (ITU-R, СИ). Всё, что не следует из стандарта, помечено **[проект]** — это
  проектное решение RICON, его можно менять конфигом или новой версией документа.
- Уровни: **MUST** — обязательно; **SHOULD** — желательно; **MAY** — допустимо.
- Проверка каждого требования: **OR** — oracle-вектор (эталон на Python stdlib), **CT** — contract-тест,
  **WB** — компиляция в Workbench, **DOC** — проверка документа.
- Нефизические поля (идентификаторы, epoch/seq/TTL, версии, владение и время жизни объектов, реестры,
  сериализация, authority) задаёт `docs/req/REQ-core-contracts.md` (codex). Он ссылается на id отсюда.

## 1. Область

**Входит:** оценка одной ноги «передатчик → приёмник» на уровне L0 и каркас для следующих слоёв: сумма потерь,
мощность на входе приёмника, шум (тепловой, приёмника, внешний), помеха, SINR, разборчивость, состояние.

**Не входит:** алгоритм дифракции L2 (ITU-R P.526 — OPEN, редакция -16 не подтверждена); рельеф, объекты,
погода, многолучёвость (будущие слои по этому же контракту); диаграммы антенн (seam `AntennaPattern`);
модель помех (seam `InterferenceModel`); маршрут из нескольких ног (`REQ-core-contracts`).

## 7. Шум и помехи

| id | Требование | Источник | Проверка |
|---|---|---|---|
| REQ-LE-60 | Тепловой шум в полосе: `N₀ = 10·lg(k·T₀·B·1000)` дБм (≈ −173.975 дБм/Гц + `10·lg B`) | СИ | OR, допуск 0.01 дБ |
| REQ-LE-61 | Коэффициент шума системы: `f_sys = f_a + f_r − 1`, где `f_r = 10^(NF/10)`, `f_a = 10^(F_a/10)`. Шум системы `N = N₀ + 10·lg f_sys`. **Вывод из определений** (антенна и линия без потерь): по определению коэффициента шума приёмник, нагруженный на источник с температурой `T₀`, добавляет мощность `(f_r − 1)·kT₀B`; по определению `f_a` внешний шум, принятый антенной, равен `f_a·kT₀B`. Сумма — `(f_a + f_r − 1)·kT₀B`. Потери в линии/антенне — будущий параметр | определение `f_a = p_n/(k·t₀·b)` — ITU-R P.372 (W2:39, REF); определение коэффициента шума — общая радиотехника | OR |
| REQ-LE-62 | Внешний шум `F_a` даёт seam `NoiseModel` по категории REQ-LE-17. Модель по умолчанию — медиана техногенного шума `F_am = c − d·lg f`: город 76.8/27.7, жилая 72.5/27.7, сельская 67.2/27.7, тихая сельская 53.6/28.6; галактический 52.0/23.0 | ITU-R P.372-11 по отчёту FFI (W2:37-38, W2:61) — REF; редакция P.372 — OPEN | OR |
| REQ-LE-63 | Область модели REQ-LE-62 — **0.3–250 МГц**. Вне области модель **не экстраполирует**: она отвечает «вне области», и берётся `f_a = 1` (шум антенны при `T_a = T₀ = 290 К` — та же опора, к которой отнесён `NF`; тогда `f_sys = f_r` и `N = N₀ + NF`), а бюджет несёт признак `noiseModelInDomain = false`. Значение `f_a = 0` запрещено: оно занизило бы шум ниже опорного (`f_sys = f_r − 1`) — поправка codex id472. Другая модель для >250 МГц (например, по Hagn, W2:40) — отдельная регистрация | W2:37, W2:40 | OR (450 МГц → признак) |
| REQ-LE-64 | Категория «нет» — внешний шум сверх опорного не учитывается: `f_a = 1`, `N = N₀ + NF` (лабораторный режим) [проект] | — | OR (V5) |
| REQ-LE-65 | Агрегат помех (считает `InterferenceModel`): `I = 10·lg Σ 10^(I_j/10)`; шум+помеха: `N+I = 10·lg(10^(N/10) + 10^(I/10))`. Нет помехи — `N+I = N` | сложение мощностей | OR |
| REQ-LE-66 | Суммы мощностей вычисляются численно устойчиво: вынести максимум (`m + 10·lg Σ 10^((x_j − m)/10)`), чтобы не было переполнения/обнуления float32 | — | OR (−400 и +400 дБм) |

## 8. SINR, порог приёма, разборчивость, состояние

| id | Требование | Проверка |
|---|---|---|
| REQ-LE-70 | `SINR = P_rx − (N+I)` (дБ) | OR |
| REQ-LE-71 | Порог приёма: если задана `S` — использовать её; если задано `SINR_min` — `S = N₀ + NF + SINR_min` (собственный шум приёмника, без внешнего и помех) [проект: порог — свойство приёмника, а не эфира] | OR |
| REQ-LE-72 | `P_rx < S` ⇒ состояние **LOST** («шумоподавитель закрыт»), разборчивость 0 | OR |
| REQ-LE-73 | Разборчивость `Q ∈ [0, 1]` даёт seam `IntelligibilityModel(SINR, параметры)`. Требования к любой модели: монотонно не убывает по SINR; для любого конечного SINR результат конечен и в `[0, 1]`; параметры — только из **явного версионированного конфига**, в коде значений по умолчанию нет | CT |
| REQ-LE-74 | **Production-модели разборчивости пока нет: `BLOCKED_CALIBRATION`** — до первоисточника (например, методики индекса разборчивости речи ANSI S3.5, не загружена), измерений или решения владельца. Для тестов seam есть фикстура `linear_test` (**TEST_ONLY**, не модель речи): `Q = clamp((SINR − a)/(b − a), 0, 1)` с параметрами фикстуры `a = −15`, `b = +15` дБ. Демодуляционный выигрыш (FM и др.) на L0 не моделируется (поправка codex id475) | CT (self-test фикстуры) |
| REQ-LE-75 | Если `P_rx ≥ S`: **CLEAN** при `Q ≥ Q_clean`, **DEGRADED** при `Q ≥ Q_deg`, иначе **WEAK**. Пороги — только из версионированного конфига; production-значения — `BLOCKED_CALIBRATION` вместе с REQ-LE-74. Фикстура тестов: `Q_clean = 0.8`, `Q_deg = 0.5` (TEST_ONLY) | CT |
| REQ-LE-76 | Смысл WEAK: приёмник открыт, но SINR снижен внешним шумом или помехой. Без внешнего шума и помех WEAK может не возникать — это свойство модели, а не ошибка. Проверка конфига: пороги `0 ≤ Q_deg ≤ Q_clean ≤ 1`, иначе ошибка конфигурации | CT |

## 9. Корректность чисел и отказы

| id | Требование | Проверка |
|---|---|---|
| REQ-LE-80 | Результат оценки всегда несёт `valid` и причину отказа. Перечень кодов — единый, в `REQ-core-contracts` §4 и §11 (например `INVALID_COORDINATE`, `INVALID_FREQUENCY`, `OUT_OF_MODEL_DOMAIN`, `INVALID_SENSITIVITY`); здесь требуется лишь: нарушение домена раздела 3 — код «плохой вход», частота `f > 0` вне диапазона модели — код «модель неприменима», нечисловой результат — код «численный сбой». **Порядок проверок фиксирован** (сообщается первая нарушенная граница): координаты → `f` → `B` → `P_tx` → усиления → `NF` → «ровно один порог» → значение порога → помеха → `bandId` → `modelId` → категория шума → модель разборчивости → домен модели | CT; OR (векторы с двумя нарушениями) |
| REQ-LE-81 | При `valid = false`: состояние LOST, `Q = 0`, все числовые поля бюджета конечны (не `NaN`/`Inf`) | CT (NaN/Inf в каждом входном поле, включая координаты) |
| REQ-LE-82 | При `valid = true` **все** выходные поля конечны (`P_rx`, все слои, `N₀`, `N`, `N+I`, `SINR`, `Q`). Бюджет отдаёт их раздельно: `thermalNoiseDbm` (N₀), `noiseDbm` (N), `noisePlusInterferenceDbm` (N+I), `sinrDb`, `noiseModelInDomain` — чтобы oracle проверял шум послойно | OR |
| REQ-LE-83 | «Конечно» = `−float.MAX ≤ v ≤ float.MAX` (NaN не проходит ни одно сравнение, ±Inf за границей). Без произвольных порогов вроде `1e30` | `EN/interfacefloat.html:126-127` | CT + WB |
| REQ-LE-84 | Разборчивость для любых конечных SINR (в т.ч. ±400 дБ) вычисляется без переполнения float32 | OR |

## 12. Открытые вопросы

1. Production-модель разборчивости и пороги состояний (REQ-LE-74/75) — `BLOCKED_CALIBRATION`: нужен первоисточник
   (ANSI S3.5 или иной), измерения или решение владельца. Понадобится не позже Э5 (вертикальный срез) — тогда
   вопрос `[Решение]` владельцу.
2. Действующая редакция ITU-R P.372 (W2:68) и полные тексты ITU — не загружены (itu.int недоступен). Формула
   REQ-LE-61 выведена из определений и от редакции не зависит; от неё зависят константы `c`/`d` REQ-LE-62.
3. Модель внешнего шума выше 250 МГц — не выбрана (REQ-LE-63).
4. Демодуляционный выигрыш (FM, цифровые режимы) — вне L0; нужен ли он в M1 — решение при Э4.
