# GW — земная волна над гладкой однородной Землёй (P.368-10, LFMF)

Версия 0.1, 2026-10-24, **DRAFT** — на слепую проверку codex.
Автор REQ и эталона: claude; независимая проверка: codex (без авторского `oracle/ground_wave_oracle.py`).
Основание: аудит диапазонов (`docs/plan/AUDIT-bands-summary.md` §4 п. 1) и сравнение кандидатов
(`docs/evidence/E-ground-wave-candidates.md`, воспроизведено codex #3813): на 20–30 МГц у RICON нет модели наземной
трассы, основной кандидат для гладкой Земли — C1 LFMF.

## Назначение и границы

**GW01.** Чистая функция вычисляет основные потери передачи земной волной над гладкой однородной сферической Землёй
для одной частоты, расстояния, пары высот и одного профиля грунта. Это host-эталон: native-контракт (binary32,
допуски, производительность) — отдельная ревизия после анализа точности функций Эйри в binary32.
Не входят: рельеф и дифракция на холмах, смешанные трассы суша/вода (P.368 Annex 2, Millington), пространственная
(ионосферная) волна, шум, усиления реальных антенн, разборчивость, подключение к оценщику связи и L2.
Ниже 30 МГц production L2 по-прежнему отказывает; эта функция его не заменяет и не меняет.

Первоисточник: [ITU-R P.368-10](https://www.itu.int/rec/R-REC-P.368-10-202208-I/en) (08/2022), Annex 1;
*recommends* 1 называет интегральную программную реализацию частью Рекомендации. Используемая реализация —
NTIA/ITS LFMF v1.1 (https://github.com/NTIA/LFMF, main.zip sha256
`be6ed041d4f095c8845e8cce800e1a4ffb568401dec6f5d93c14b7a8ce58fd95`), US public domain, производные работы разрешены
с пометкой изменений (`LICENSE.md` NTIA). Требования ниже о кодах, полях и диагностике — проектные решения RICON.

## Вход и порядок проверок

**GW02.** Вход — ровно `{frequencyMHz, distanceKm, txHeightM, rxHeightM, polarization, surfaceRefractivityN, ground}`,
`ground` — ровно `{epsilonReal, conductivitySm, provenance}`. Числа — конечные int/float JSON (bool, строки, null,
NaN/Inf — не числа); вычисление в binary64 без предварительного округления к binary32. Лишние и отсутствующие поля
запрещены; JSON-загрузчик отвергает повторяющиеся ключи до создания dict/map.
`polarization` — строка `"V"` или `"H"`; `provenance` — `SOURCE_DOMAIN`, `ASSUMED_CONFIG` или `TEST_ONLY`
(задаёт вызывающая сторона, функция его не удостоверяет и не повышает).

**GW03.** Первый подходящий код определяет результат; при отказе результат содержит только `code`:
1. `INVALID_INPUT`: нарушена структура или тип GW02; frequencyMHz ≤ 0; distanceKm ≤ 0; высота < 0;
   surfaceRefractivityN < 0; epsilonReal < 1; conductivitySm < 0.
2. `OUT_OF_MODEL_DOMAIN` (физически допустимый вход вне области метода), проверки в этом порядке:
   txHeightM > 50, rxHeightM > 50, frequencyMHz ∉ [0.01, 30], surfaceRefractivityN ∉ [250, 400],
   distanceKm ∉ [0.001, 10000], conductivitySm = 0, polarization = `"H"`.
   Границы включены, как в `ValidateInputs.cpp` LFMF v1.1. H отвергается: P.368 Annex 1 даёт вертикальную
   составляющую поля, выход LFMF для H — результат реализации без источника (`E-ground-wave-candidates.md` §2).
3. `NUMERIC_FAILURE`: вычисление не дало конечного положительного поля — корень w1'(t) − q·w1(t) = 0 не сошёлся за
   25 итераций Ньютона, центр разложения функции Эйри вне таблицы, деление на ноль, переполнение exp, нулевое или
   не конечное поле. LFMF v1.1 в этих случаях прерывается исключением или возвращает SUCCESS с ±inf.
4. `OK`: результат по GW05.

## Метод

**GW04.** Расчёт — алгоритм LFMF v1.1 без изменений формул, констант и порогов (DeMinco NTIA Report 99-368,
Hufford NTIA 87-219, Wait 1956):
- a₀ = 6370 км; эффективный радиус aₑ = a₀ / (1 − 0.04665·exp(0.005577·Nₛ)); θ = d/aₑ; k = 2π·1000/λ (рад/км);
  ν = (aₑ·k/2)^{1/3};
- η = ε′ − j·σ/(ε₀·2π·f), ε₀ = 8.854187817e-12 Ф/м; Δ = √(η − 1), для V: Δ = √(η − 1)/η; q = −j·ν·Δ;
- d < 80/f_MHz^{1/3} км — плоская Земля с поправкой на кривизну (функция Фаддеевой ACM 680, ряд при |q| ≤ 0.1),
  иначе ряд вычетов (до 200 корней, останов при |G/ΣG|₁ < 0.0005); высоты — функции высоты-усиления;
- нормированное поле умножается на E₀ = √(η₀·P·G/(4π))/d, η₀ = 119.9169832·π Ом, G = 10^{0.477};
- основные потери A = 10·log10(P·G) + 10·log10(4π·η₀) + 20·log10(f_Гц) − 20·log10(E/1000) − 20·log10(c),
  c = 299792458 м/с; не зависят от P.

Эталон RICON (`oracle/ground_wave_oracle.py`) — перенос LFMF на Python stdlib с перечнем изменений в шапке; таблицы
функций Эйри извлекаются скриптом из исходника (`docs/evidence/receipts/ground-wave-airy-tables-claude.py --check`).
Эквивалентная реализация допустима, если на корпусе совпадает с неизменённой сборкой LFMF v1.1 в пределах GW08.

## Выход

**GW05.** При OK результат — ровно `{code, basicLossDb, fieldDbuVm, method, kr, heightToWavelength, provenance}`:
- `basicLossDb` — A по GW04. Это Lb P.368 Annex 1 NOTE 1 (Lb = 142.0 + 20·log10 f_MHz − E), но с константой,
  которую дают константы LFMF: A + E(1 кВт) − 20·log10 f_MHz = 141.98599025116266 дБ. Округлённые 142.0 в NOTE 1
  отличаются на 0.014 дБ; эталон и потребители используют A, а не формулу с 142.0;
- `fieldDbuVm` — E в дБ(мкВ/м) для опорного излучателя P.368 Annex 1: 1 кВт, 300 мВ/м на 1 км (P = 1000 Вт);
- `method` — `FLAT_EARTH_CURVE` или `RESIDUE_SERIES` (выбор по GW04);
- `kr` — k·r = 2π·d/λ без единиц, диагностика P.368 Annex 1 NOTE 3;
- `heightToWavelength` — max(txHeightM, rxHeightM)/λ, диагностика без вердикта (`E-ground-wave-candidates.md` §2);
- `provenance` — копия `ground.provenance`.
Высоты TX и RX симметричны: перестановка не меняет результат (LFMF берёт меньшую и большую). Вход не изменяется.

**GW06. Конвенция антенн** (исправлено по counter codex #4056). `basicLossDb` — основные потери передачи Lb в
смысле ITU-R P.341 (между изотропными антеннами) и P.368 Annex 1 NOTE 1. Усиление опорного излучателя LFMF —
короткий вертикальный монополь на идеально проводящей плоскости, G = 10^{0.477} (4.77 dBi вместе с изображением) —
входит только в нормировку поля E₀ и в потерях сокращается: при нормированном поле 1 A равно потерям свободного
пространства 20·log10(4πd/λ) (подстановка codex; эталон: |Δ| ≤ 2e-14 дБ, тест
`test_unit_field_gives_free_space_loss`). Поэтому потребитель прибавляет к Lb усиления своих антенн относительно
изотропной, включая влияние земли у антенны, а 4.77 dBi LFMF автоматически не прибавляет и не вычитает. Определение
этих усилений для реальных антенн у земли (P.341 Table 1 и Annex 3, КПД штыря, высота) — интеграционный REQ;
автоматические поправки ±6.02 / ±9.54 дБ здесь запрещены (`E-ground-wave-candidates.md` §2 — ASSUMED_DIAGNOSTIC).

## Область применимости (не код, а условия использования)

**GW07.** Вызывающая сторона отвечает за то, чтобы условия P.368-10 выполнялись; функция их не проверяет:
- *recommends* 2 — только когда ионосферные отражения пренебрежимы; на 20–30 МГц пространственная волна возможна и
  здесь не моделируется;
- *recommends* 3 и NOTE 1 к нему — не для приёмной антенны высоко над поверхностью; количественный предел
  h = 1.2·σ^{1/2}·λ^{3/2} дан лишь при εᵣ ≪ 60λσ. Предел 50 м в GW03 — проверка программы, не физика;
- Annex 1 — гладкая однородная Земля; NOTE 4 — эффективная высота над средним рельефом трассы — задача интеграции;
- NOTE 2 — разброс по месту приёма (лог-нормальный, 3–4 дБ) сюда не входит и не должен дублироваться с P1b;
- NOTE 3 — при kr < ~10 погрешность метода не ограничена 1 дБ; поправка ближней зоны NOTE 3 не применяется.

## Приёмка

**GW08.** Корпус `oracle/vectors/ground_wave_v1.json` хранит LF SHA-256 этого REQ, версию/ревизию, происхождение
ожиданий и признак JSON-only. Обязательны: 20, 25, 30 МГц и стык 30 МГц; суша и вода (оба края профиля WL02 P.527,
S = 0 и 35 ‰) и сухой/влажный грунт TEST_ONLY; расстояния 1 м–10 000 км, включая обе стороны порога метода
80/f^{1/3}; высоты 0, 1, 2, 10, 50 м и перестановка TX/RX; Nₛ 250/301/400; все коды и границы GW03 по отдельности;
порядок отказов; H; JSON-типы и лишние/отсутствующие поля; 95 строк опубликованных примеров NTIA
`LFMF_Examples.csv` (NTIA/LFMF-test-data, zip sha256 `53f5331b…a2be6`; точная копия CSV —
`oracle/data/lfmf_examples_ntia_v1.csv`, sha256 `c13ef54e…0ff6`). Примеры NTIA содержат H, произвольные мощности и
коды отказа LFMF, поэтому проверяются на уровне программы LFMF (`ntiaExamples`), а не через контракт GW02–GW05.
- Ожидания численных полей — из эталона, сверенного с неизменённой сборкой LFMF v1.1 (driver
  `docs/evidence/receipts/ground_wave_ntia_driver_claude.cpp`): |Δ| ≤ 2e-9 дБ при печати сборки с 9 знаками;
  для строк NTIA дополнительно |эталон − опубликованное| ≤ 0.05 дБ (там 1 знак после запятой).
- Host сравнивает коды, `method` и `provenance` точно; `basicLossDb`, `fieldDbuVm` с abs ≤ 1e-8 дБ;
  `kr`, `heightToWavelength` с rel ≤ 1e-12. Инвариант: basicLossDb + fieldDbuVm − 20·log10 f = 141.98599025116266
  (≤ 1e-9 дБ) — он проверяет, что поле и потери взяты из одного расчёта.
- Независимая проверка codex — по этому REQ, P.368-10 и LFMF v1.1, без авторского эталона.
Это вычислительная приёмка формулы и программы, не измерение связи в игре.
