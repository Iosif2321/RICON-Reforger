# CT10 lifecycle: отдельный HOST ordered protocol

2026-11-10. **VERIFIED_HOST_PROTOCOL_CANDIDATE / HOST_PROTOCOL_ONLY**. Автор Core, независимые тесты Reviewer; scoped verdict Agora #8293/#8294. Canonical publisher — codex.lead. Raw temporal Receiver.full_resync, v1, RCFD/1 и Enforce не меняются.

Термин authenticated в этом HOST-контракте означает проверку отдельной доверенной caller-квитанции. Происхождение реального RPC, правдивость current-authority exporter и retired-epoch защита на стороне источника этим модулем не доказаны.

## Exact API и records

`OrderedReceiver(owner_player_id, limits=temporal_snapshot_oracle.DEFAULT_LIMITS)`; `apply(now_ms,envelope,authority)`; `read(link)` возвращает detached Snapshot2 либо None; `visible(now_ms,link)` — bool; `state()` — detached state. Existing three limits: maxSnapshots/maxDescriptorBytes/maxTotalDescriptorBytes; maxTracked(active+closed) и maxItems равны maxSnapshots. Никакого physics kernel: reuse temporal typed/validate/preflight и CF/CD.

Envelope имеет ровно `{protocolVersion,kind,ownerPlayerId,sessionEpoch,deliverySeq,linkIdHighWater,items}`: protocolVersion=1; kind FULL/DELTA; owner ID 1..MAX; epoch/deliverySeq 1..MAX-1; high-water H 0..MAX. Все int — strict int32 без bool/float/string coercion. Items list ограничен maxItems, один item на linkId. FULL содержит только ACTIVE. Union:

- ACTIVE: ровно `{kind:"ACTIVE",snapshot:Snapshot2}`; descriptor обязателен даже при LOST/Q0.
- END: ровно `{kind:"END",end:EndRecord}`. EndRecord имеет ровно `{sessionEpoch,linkId,linkSeq,talkerPlayerId,listenerPlayerId,binding,reason}`; epoch/seq 1..MAX-1, IDs1..MAX, players различны, binding — existing Snapshot2 binding. Ни descriptor, ни state/Q, ни TTL.

END reason — ровно TTL_EXPIRED, CLIENT_STOP, DISCONNECT, RECONNECT, ENTITY_CHANGED, ENTITY_INACTIVE, ACCESS_LOST, POWER_LOST, DEVICE_REMOVED, CATALOG_INVALIDATED, SESSION_ROTATED, ADMIN_REVOKED, TICK_ANOMALY либо LINK_REMOVED. Это existing `RICON_ELeaseTerminalReason` без NONE + authoritative eligibility/route withdrawal LINK_REMOVED; RF LOST/Q0/UNKNOWN/resource не дают END.

TTL_EXPIRED означает authoritative **lease expiry**, не local presentation TTL и не descriptor physical validity. `visible=false` само по себе END не порождает. END не изменяет physical kernel или исходный descriptor; после удаления active clone этот control oracle не хранит persistent medium. Реальная непрерывность среды/source builder между передачами этим срезом не проверена.

Authority — отдельный trusted caller record, ровно `{ownerPlayerId,sessionEpoch,deliverySeq,kind,linkIdHighWater,activeExpected,endedTargets}`. Header independently pins transaction/owner/epoch/H. `activeExpected` — map<strict positive int, existing ExpectedLink>, **COMPLETE POST-TRANSACTION ACTIVE SET для FULL и DELTA**. `endedTargets` — map<id, exact EndRecord>, ровно для END items. У **обеих** maps key==record.linkId, record.sessionEpoch==authority.sessionEpoch и record.listenerPlayerId==authority.ownerPlayerId; Expected.channel tx/rx обязаны совпасть с собственным Expected.binding. Это internal receipt consistency до наблюдений, не сравнение с obsolete actual snapshot. FULL endedTargets пуст. Snapshot и END listener всегда равны constructor owner независимо от Expected. Receipt не извлекается из packet и не является authentic RPC proof.

State имеет ровно `{ownerPlayerId,sessionEpoch,deliverySeq,checkpointHighWater,seenHighWater,observedEpoch,observedDeliverySeq,observedHighWater,needsFull,active,closed}`. Initial epoch/observedEpoch=None, seq/H=0, needsFull=true. Active[id] — `{snapshot,receivedAtMs,expected}`; closed[id] — EndRecord. Reads/state/retained validated records detached; raw input читается синхронно без whole-input deepcopy до caps. Constructor валидирует три scalar limits до копирования. Floors, expired active state и tombstones не удаляются по TTL.

Apply возвращает ровно `{code,needsFull,deliverySeq}`. Основные codes: ACCEPT_FULL, ACCEPT_DELTA, STALE, NEED_FULL, GAP, INVALID_INPUT, INVALID_AUTHORITY, INVALID_END, BATCH_LIMIT, DUPLICATE_LINK, HIGH_WATER_ROLLBACK, CLOSED_ID, BINDING_MISMATCH, LINK_SEQUENCE_ROLLBACK, LINK_SEQUENCE_CONFLICT, COMPLETENESS_MISMATCH, RESOURCE_LIMIT плюс неизменённые temporal admission codes.

## Порядок и атомарность

Header domain/owner и current authority epoch проверяются до same-epoch seq comparison: новый epoch нельзя отбросить из-за seq1 после прежнего seq10. Epoch непрозрачен; numeric `>` не определяет authority. Только certified FULL может установить новый epoch; DELTA требует existing identity и needsFull=false.

Same-epoch envelope deliverySeq<=committed deliverySeq либо тому же observedEpoch/observedDeliverySeq — STALE: без обхода payload, receivedAt/needsFull/frontiers/identity не меняются. **Любой INVALID_AUTHORITY полностью inert**, включая flags и observed metadata. Для свежего проверенного scope DELTA допускает только committed last+1; gap либо invalid fresh transaction сохраняет payload/cache/committed sequence/checkpoint и выставляет needsFull=true. Visible пока needsFull=false и local elapsed в [0,ttl); needsFull скрывает presentation как technical desync, не выполняет audio/mute/доставку.

FULL может перепрыгнуть deliverySeq только с independently matching authority и строго превысить **prior observedDeliverySeq этого scope**. После полной проверки authority/всех END receipts и каркаса tagged items, но **до ACTIVE payload domains, gap и retained capacity**, фиксируются bounded authenticated control observations. Поэтому malformed ACTIVE descriptor в initial/new-epoch FULL тоже сохраняет authenticated pending frontier. observedEpoch/observedDeliverySeq/observedHighWater хранят ровно один текущий authority scope; при совпадении с committed epoch монотонно растёт и seenHighWater. Это не payload commit и не advance committed deliverySeq. Failed new-epoch FULL хранит pending observations отдельно, не затирает old committed epoch/checkpoint/seen floor. Recovery FULL обязан покрыть prior observedHighWater и committed seenHighWater своего epoch; current frame сравнивается с **prior**, затем наблюдение записывается. Invalid fresh FULL не вызывает raw Receiver.full_resync и не очищает старые данные. Это новая отдельная boundary, не изменение raw-full semantics.

Пер-link в same epoch: меньший linkSeq относительно сохранённого active/tombstone отвергает **весь** свежий frame; equal+changed normal payload — LINK_SEQUENCE_CONFLICT; equal+identical ACTIVE/END — idempotent row без receivedAt/slot изменений, но owner deliverySeq transaction advances. Для уже active ID binding/players неизменны даже при большем seq. END после active требует строго большего seq (equal меняет union kind и конфликтует), сохраняет старую адресность и закрывает ID. Trusted END невиданного ID>checkpointH допустим как coalesced create/end, хранит tombstone. END уже implicit-closed ID<=checkpointH — проверенный idempotent no-op: per-link seq после checkpoint pruning больше не хранится, barrier запрещает любую ACTIVE resurrection. ACTIVE explicit/implicit closed ID не открывает даже с большим seq.

После любой candidate transaction active IDs обязаны точно равняться keys(activeExpected). Все retained snapshots повторно проверяются с current Expected через existing temporal preflight: old generation/RF/owner grant не остаётся valid до TTL при DELTA, обновляющей другой link. Budget active descriptors и combined(active+closed) cap проверяются до commit. Complete authority maps могут описывать post-state больше локального maxTracked: это валидная authority, затем RESOURCE_LIMIT, не INVALID_AUTHORITY. Для record shape остаётся общий абсолютный предел 65536 из existing limits domain. При полном closed budget нужен fresh FULL; floors не вытесняются ради PASS.

## Checkpoint barrier без неограниченной истории

H каждого принятого frame не меньше prior authenticated high-water; все item IDs<=H. Аутентифицированный rejected END3/H3 при capacity уже поднимает observed high-water, поэтому FULL H2 не может забыть его; gap deliverySeq5 не может лечиться FULL seq4 даже при том же H. DELTA не создаёт checkpoint barrier. Same-epoch FULL требует H>=seenHighWater и H>=checkpointHighWater; pending-scope FULL также H>=observedHighWater. FULL active set independently certified; каждый отсутствующий ID<=H становится permanently closed для epoch. ID<=предыдущего checkpointH допускается ACTIVE только если ещё находится в текущем active; explicit closed также запрещён. Проверка resurrection выполняется **до** pruning.

Успешный FULL атомарно заменяет active set, устанавливает checkpointHighWater=seenHighWater=H, deliverySeq и needsFull=false, затем удаляет все closed records: H покрывает authenticated observations. Barrier+active IDs сохраняют запрет resurrection без списка всех закрытых ID. Equal-linkSeq retained ACTIVE сохраняет прежний receivedAt. Lower/equalchanged FULL отвергается целиком. При новой certified epoch old floors/maps заменяются; повторное использование ID разрешено только в новом scope. Current-authority exporter обязан не возвращаться к retired epoch и выдавать правдивый complete active set: HOST dict сам этого не доказывает, unbounded retired-epoch/payload history здесь не вводится. При исчерпании seq/ID нужен authority rotation, без wrap.
