## Назначение

**MP01.** Чистая функция вычисляет ε′ и σ для одной частоты по явно выбранному профилю.
Она заполняет `material` контракта MS03 (`REQ-material-slab.md`), не меняя ядро пластины.
P3.1 уже выбирает ID; второй resolver, выбор по названию объекта и неявный профиль по умолчанию не нужны.
Геометрия стен/проёмов, поляризация, многослойные конструкции, потери целого дома и звук сюда не входят.

Первоисточник: [ITU-R P.2040-4](https://www.itu.int/rec/R-REC-P.2040-4-202509-I/en),
Annex §3, (57)–(58), Table 3, PDF-страницы 27–28 (печатные 25–26).
Параметры таблицы — примеры измеренных материалов, не свойства любого объекта такого класса.
Положения о binary32, кодах отказа и совместимости с MS03 ниже — проектные требования.

## Вход и приоритет проверок

**MP02.** Вход — ровно `{frequencyMHz, profile}`. Частота — положительное конечное binary32.
Все численные поля сначала округляются к binary32; bool, null, строки, NaN/Inf и переполнение не числа.
Субнормальные конечные значения допустимы. Лишние и отсутствующие поля запрещены.

`profile` — ровно `{a, b, c, d, minMHz, maxMHz, maxInclusive, provenance}`:

- a > 0, c ≥ 0; b и d — конечные знаковые числа;
- 0 < minMHz ≤ maxMHz; нижняя граница включена, верхняя включена только при `maxInclusive=true`;
- `maxInclusive` — именно bool; при minMHz=maxMHz он обязан быть true;
- `provenance` — ровно `SOURCE_DOMAIN`, `ASSUMED_CONFIG` либо `TEST_ONLY`.

Числа в каталоге хранят исходную десятичную запись, округление происходит при вызове.
Происхождение задаёт доверенная вызывающая сторона, функция не удостоверяет его и не повышает.
JSON-загрузчик отвергает повторяющиеся ключи до создания dict/map.

**MP03.** Первый подходящий код определяет результат. При отказе результат содержит только `code`:

1. `INVALID_INPUT`: структура корня или частота нарушают MP02.
2. `INVALID_PROFILE`: профиль нарушает MP02, даже если частота вне его полосы.
3. `OUT_OF_MODEL_DOMAIN`: частота вне [1,450000] МГц либо вне полосы профиля с учётом maxInclusive.
4. `NUMERIC_FAILURE`: вычисленное положительное значение не представимо конечным ненулевым binary32;
   в частности, положительная проводимость не превращается в ноль из-за underflow.
5. `NUMERIC_DOMAIN_LIMIT`: округлённое ε′ вне [1,100] либо σ > 1e8, то есть вне численного среза MS03.
6. `OK`: результат ровно `{code, material}` по MP05.

Проверка численной представимости MP03.4 выполняется для обоих параметров до MP03.5.
Положительность определяется коэффициентами a>0 / c>0, а не вычисленным результатом: потеря до нуля
в binary64 и последующее округление в binary32 к нулю одинаково являются NUMERIC_FAILURE.
Отказ не означает воздух, нулевые потери, LOST или границу всех путей.

## Формулы и выход

**MP04.** fGHz = frequencyMHz / 1000; ε′ = a·fGHz^b; σ = c·fGHz^d (См/м).
σ=0 точно, если c=0, независимо от d. Нулевой показатель даёт сам коэффициент точно.
Иначе устойчивая форма: exp(ln(coefficient) + exponent·ln(fGHz)); она избегает переполнения
отдельной степени при конечном произведении. Эквивалентный устойчивый алгоритм допустим.
Host вычисляет в binary64 после округления входа, затем округляет ε′ и σ к binary32.
Прямая степень на умеренных числах служит независимой проверкой преобразования.

**MP05.** `material` — ровно `{epsilonReal, conductivitySm, minMHz, maxMHz, provenance}`.
ε′ и σ — результаты MP04; обе границы равны округлённой входной frequencyMHz, а не всей полосе fit.
Так частотно-зависимое значение не используется как константа на другой частоте.
Происхождение копируется без изменения. Вход не меняется; результат и material создаются заново.
Отдельная цепь профиль → MS03 проверяет реальные вызовы существующего slab, не копию его формул.

## Каталог примеров и его границы

**MP06.** `oracle/data/material_profiles_p2040_v1.json` — версионированные численные примеры Table 3.
Каждая строка имеет уникальный ID, русскую подпись, номер строки и отдельный профиль.
Одинаковое имя материала не склеивает разные измерения, перекрывающиеся полосы или разрывы.
Три части floorboard имеют исключённую верхнюю границу; для остальных строк диапазон закрыт.
Номер строки считается после шапки Table 3, с продолжением на следующей странице; каждая часть floorboard
с отдельным коэффициентом c/d считается строкой.

Профиль `SOURCE_DOMAIN` из этого каталога не экстраполируется вне своей полосы. Стандарт допускает,
что полосы измерений не являются абсолютными пределами формулы (кроме трёх грунтов 1–10 ГГц), но проект
требует отдельного обоснованного профиля или явного ASSUMED_CONFIG для новой полосы, без смены метки исходной строки.
На 20–76 МГц здесь доступны воздух и первая строка wood. Бетон, кирпич и металл на УКВ таблицей не закрыты;
NIST, неоднородность/влажность/армирование и материал реального объекта требуют отдельного evidence.
Строки грунта — примеры свойств, не модель распространения вдоль поверхности и не замена P.527.

Каталог имеет ровно `{schema, version, source, note, profiles}`. schema=`ricon.material_profiles.p2040`, version=1,
source — ссылка на P.2040-4 выше; profiles — непустой объект ID → `{labelRu, sourceRow, profile}`.
ID удовлетворяет OP02; sourceRow — положительный int без bool, строки не повторяются; подпись непустая.
Список содержит все 38 строк Table 3; в этом каталоге все provenance=`SOURCE_DOMAIN`.
Загрузчик проверяет структуру и каждый профиль, не только выбранный. Изменение каталога требует ревизии корпуса.

## Приёмка

**MP07.** Корпус `oracle/vectors/material_profile_v1.json` хранит LF SHA-256 этого REQ и каталога,
версию/ревизию, происхождение ожиданий, признак native для каждого случая. Freeze — после blind-check Claude,
который читает только REQ, каталог, первоисточник и вход/ожидание JSON, не авторские oracle/build/test.

Обязательны: все строки каталога на нижней/верхней границах и внутри полосы; исключённые границы floorboard;
разрывы/перекрытия без автоматического выбора; MHz→GHz; a/c-константы; c=0 при большом d; отрицательные показатели;
представимость, underflow положительной σ, пределы MS03; точечный профиль; порядок отказов; JSON-типы/поля;
неизменность входов/выходов; независимая прямая формула; профиль→slab на правильной и другой частоте.
JSON-only случаи отдельно отмечены; значение null у profile проверяется и в native.

Host сравнивает ожидаемые коды/поля/происхождение точно, численные значения с rel=1e-12, abs=0.
Предварительный native допуск параметров: относительная ошибка ≤2e-5 для положительного эталона,
ноль точно; minMHz/maxMHz и коды/происхождение точно. Допуск не допускает подмены положительного σ нулём.
Критерий цепи slab остаётся MS08. Это вычислительная приёмка, не измерение радиосвойств стены в игре.
