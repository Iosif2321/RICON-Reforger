# P1b.1: конечная сумма составляющих полезного канала

Версия **0.1 DRAFT**, 2026-10-23. Автор требований/эталона codex, checker и Enforce — claude.
Основание: REQ-channel-time v0.2, Agora #3327/#3505/#3506. До согласования и freeze native-код не пишется.

## Назначение и границы

**CF01.** `FINITE_MULTIPATH_V1` — чистое вычислительное ядро узкополосного, локально стационарного канала.
Постоянные на интервале относительные мощности складываются как комплексные амплитуды; доплер изменяет фазу.
Результат — мгновенный коэффициент **среды**, взаимный для одной физической пары и частоты. Направленные
TX/RX-профили, средний бюджет L0/L1/L2, шум, помехи, демодуляция и доставка остаются снаружи.

Основание физической операции: [ITU-R P.1407-8](https://www.itu.int/rec/R-REC-P.1407/en), Annex 1 §6,
ур. (21)–(23). Это не калибровка конкретной рации, карты или длительности просвета.
[NTIA TM-11-477](https://www.its.ntia.gov/publications/details?pub=2552) исследует ограничения классических
fading-предположений на коротких VHF/UHF интервалах; одна модель распределения не объявляется универсальной.

**CF02.** Первый срез проверяет только kernel и его входное описание. Он **не закрывает P1b целиком**.
Построитель коэффициентов из положения/движения антенн и отражателей, проверка узкополосности и локальной
стационарности, медленная тень, миграция всех потребителей снимка по CT10 и голосовой actuator ещё обязательны.
Здесь используются синтетические входы TEST_ONLY. В production профиль не включается по умолчанию.

`coverageComplete=true` — утверждение доверенного серверного builder о полноте наблюдений и применимости
его проверенного профиля на всём интервале. Сам флаг не является доказательством из мира. Клиент не вправе
поставлять такой вход серверу. Разные полные физические состояния не заменяются одним временем/seed.

## Вход и нормальная форма

**CF03.** Корень JSON имеет ровно два поля: `descriptor`, `query`. Лишние и отсутствующие поля запрещены
на JSON-границе. int32 — целое число −2147483648..2147483647, bool не int. Все дробные поля сначала
типизируются в IEEE binary32, ties-to-even/overflow→Inf, и только затем проверяются; нужны конечные значения.
Ключ — 1..64 ASCII-символа `[A-Za-z0-9_.:-]`.

`EndpointKey` — ровно `{deviceId, transceiverIndex}`: int32 deviceId≥1, transceiverIndex≥0.
Пара сравнивается лексикографически по этим двум целым; одинаковые концы запрещены.

**CF04. `descriptor`.**

| Поле | Домен/смысл |
|---|---|
| modelId | ключ; поддерживается FINITE_MULTIPATH_V1 |
| profileId, profileVersion | ключ и int32≥1; версия физического профиля, не сетевого снимка |
| a, b | EndpointKey, строго a < b; физическая пара, не leaseId/linkId |
| frequencyMHz, bandwidthHz | binary32 >0; центральная частота и полоса проверенного узкополосного профиля |
| environmentRevision | int32≥1 |
| anchorMs, validFromMs, validUntilMs | int32≥0, anchor≤from<until; фазы заданы в anchorMs с subUs=0 |
| staticChannel | bool; при true все dopplerQ обязаны равняться 0 |
| coverageComplete, resourceExhausted | bool; полнота/применимость builder и исчерпание ресурса |
| components | список ≤64 Component, упорядоченный по componentId строго по ASCII |

64 — вычислительное ограничение этого среза, не физический предел числа путей. Builder не вправе молча
отбросить остальные составляющие: при невозможности представить полный проверенный набор полнота снимается
или ставится resourceExhausted; это не LOST и не разрешение отсечки по количеству приращений.

`Component` — ровно `{componentId, powerWeight, phaseQ, dopplerQ}`.
componentId — ключ; powerWeight — binary32 в [0,1], **относительный вес мощности среды**, не RX-мощность.
phaseQ — int32 в [0,M), где M=2^30. dopplerQ — int32; область модели |dopplerQ|≤M/4.
При постоянных на интервале условиях фаза меняется линейно. EVOLVING-среда может иметь нулевые проекции
скоростей и нулевой доплер; статичная среда с ненулевым доплером — невалидный descriptor.

Явное начальное состояние выполняет CT05 «состояние или seed»; отдельный ПСЧ не требуется.
PTT/keepalive/resync/epoch отсутствуют среди входов физической модели и не могут перекинуть её фазы.

**CF05. `query`.** Ровно `{tx,rx,frequencyMHz,bandwidthHz,profileId,profileVersion,environmentRevision,nowMs,subUs}`.
tx/rx — различные EndpointKey; частота/полоса — binary32>0; environmentRevision — int32≥1;
profileId/profileVersion — ключ и int32≥1 ожидаемого профиля на доверенной стороне;
nowMs — int32≥0, subUs — int32 в [0,999]. Серверное время передаётся явно, системные часы не читаются.
Перестановка tx/rx допустима: каноническая пара должна совпасть с descriptor. Частота, полоса, профиль и ревизия
совпадают точно после типизации. Client/server clock mapping пока NOT_VERIFIED (CT06).

## Вычисление

**CF06. Фаза.** Разрешение — 1/M оборота; dopplerQ — доли оборота за микросекунду.
Частота доплера = dopplerQ·10^6/M Гц; шаг `0.0009313225746154785` Гц. Это объявленная аппроксимация модели.
При переводе физического доплера в этот формат builder обязан учитывать её ошибку на своём интервале;
здесь builder и автоматическое округление доплера ещё не реализуются.

Для неотрицательного Δms = nowMs−anchorMs:

```
tQ = ( ((Δms mod M)·1000 mod M) + subUs ) mod M
phaseQ(t) = (phaseQ(anchor) + dopplerQ·tQ) mod M
```

Остаток всегда в [0,M), в том числе для отрицательного доплера. Эталон использует точную целочисленную
арифметику. Enforce не умножает большие int32 напрямую: при H=2^15, mask=H−1, x,y∈[0,M):

```
lo = (x & mask)·(y & mask)
cross = ((x & mask)·(y >> 15) + (x >> 15)·(y & mask)) & mask
MulMod(x,y) = (lo + (cross << 15)) & (M−1)
```

Наибольшие промежуточные суммы 2147352578 и 2147385345 меньше INT_MAX. Знак доплера применяется после
положительного MulMod без вычисления abs(INT_MIN): выход за область проверяется до операции.
Глобальное время и большое произведение не преобразуются во float. Фаза при большом nowMs не теряется.

**CF07. Комплексная сумма.** W=ΣpowerWeight. Если W>0, амплитуда компонента
`a_i = sqrt(powerWeight_i)/sqrt(W)`. Такая форма сохраняет малый положительный вес без underflow деления
перед sqrt. Затем `h=Σ a_i·exp(j·2π·phaseQ_i/M)` в порядке componentId.
**Критическая RF-арифметика нормативно binary32**, чтобы условие нуля и восстановление фазы совпадали
между платформами. Каждое сложение, умножение, деление и sqrt округляется к binary32 отдельно, без FMA.
W суммируется слева направо. Каждый a_i, произведение a_i·cos/sin и прибавление в real/imag типизируются
отдельно. gainDb эталон считает binary64 по полученному binary32-модулю, native — float32.

Системные sin/cos в определении v1 не используются. Для q=phaseQ берётся ближайшая четверть:
`k=(q+M/8) div (M/4)`, `r=q−k·(M/4)`, `x=f32(f32(r/M)·f32(2π))`, где div — целое деление.
Тогда x∈[−π/4,π/4]. При r=0 полагаются sin=0, cos=1. Иначе Horner-полиномы с отдельным f32-округлением
каждого действия, коэффициенты — f32 от указанных точных дробей:

```
z = f32(x*x)
sin = x * (1 + z*(-1/6 + z*(1/120 + z*(-1/5040 + z*(1/362880 + z*(-1/39916800))))))
cos = 1 + z*(-1/2 + z*(1/24 + z*(-1/720 + z*(1/40320 + z*(-1/3628800 + z*(1/479001600))))))
```

Затем пара (cos,sin) поворачивается точно: k mod4=0 → (c,s), 1 → (−s,c), 2 → (−c,−s), 3 → (s,−c).
Это сохраняет кардинальные и противоположные фазы и малый остаток рядом с ними; приведение огромного
полного аргумента к float не требуется. Полином — версионированная численная аппроксимация, не новая физика.
Его ошибка относительно независимых binary64 sin/cos проверяется отдельно на всём приведённом диапазоне.

Модуль h вычисляется масштабированным hypot во float32, gainDb=20·log10(|h|).
Положительный gain не обрезается: конструктивная интерференция может дать усиление относительно среднего.

Нормирование — определение модели; абсолютные средние потери в powerWeight не зашиваются.
Finite-N сумма не объявляется точным распределением Релея/Райса. Сверки с такими распределениями имеют
свою область и набор профилей; они не разрешают вероятностную отсечку хвоста.

## Порядок отказов и результат

**CF08.** Сначала глобально проверяются структуры/типы/домены/порядок/уникальность и staticChannel.
Дефект последней записи запрещает ранний успешный результат. Приоритет:

1. INVALID_INPUT — любой общий дефект CF03–CF05, включая >64 components.
2. UNSUPPORTED_MODEL — корректный по схеме, но иной modelId.
3. RESOURCE_EXHAUSTED — ресурс исчерпан.
4. INCOMPLETE_COVERAGE — неполное/неподтверждённое физическое описание.
5. CONTEXT_MISMATCH — другая физическая пара, частота, полоса, profileId/profileVersion или environmentRevision.
6. STALE_DESCRIPTOR — время вне [validFromMs, validUntilMs).
7. OUT_OF_MODEL_DOMAIN — |dopplerQ|>M/4 хотя бы у одного компонента.
8. EMPTY_MEDIUM — список пуст или все powerWeight равны нулю.
9. NUMERIC_FAILURE — промежуточные RF-значения/результат не finite32.
10. ZERO_AT_SAMPLE — W>0, но вычисленный в точности модели комплексный коэффициент равен нулю.
11. OK — коэффициент и конечный gainDb вычислены.

**CF09.** Результат имеет `{code,real,imag,gainDb,phasesQ}`. При OK real/imag — коэффициент h, gainDb — число,
phasesQ — вычисленные фазы в порядке components. При ZERO_AT_SAMPLE real=imag=0, gainDb=null (не −Inf),
phasesQ сохраняется. При EMPTY_MEDIUM real=imag=0, gainDb=null, phasesQ=[]; остальные причины имеют
real=imag=gainDb=null, phasesQ=[]. Никакой код не является LOST или командой актуатору.

ZERO_AT_SAMPLE относится только к данному отсчёту и точности модели, не доказывает физический ноль на интервале.
Даже при EMPTY_MEDIUM интеграция с P1 требует независимого доказательства полноты и численной границы;
сам этот kernel не сертифицирует P1 bounds. Мгновенный ноль не удаляет descriptor/будущую полезную передачу.
Входы неизменны; результат и phasesQ не разделяют изменяемые данные с входом и другим результатом.

## Проверка и следующий gate

**CF10.** До Enforce: независимый пересчёт JSON и freeze SHA. Обязательны аналитические 1/2-компонентные
сценарии, конструктивная/разрушающая интерференция, все четверти, отрицательный доплер, большие времена,
MulMod против точной арифметики, слабый компонент при компенсации сильных, нулевые веса, статичность,
взаимность, два слушателя с разными каналами, порядок/частота вызовов и перерывы PTT без перезапуска.
Временные серии включают короткие усиления между медленными снимками и постоянно плохой канал без просветов;
частота выборки и тестовый порог явно задаются сценарием, не производственным профилем RX.

Повреждение фаз, весов, времени, model/profile версии, revision и состава массива должно ловиться отрицательными
контролями. Фазы, коды и нормативные binary32 real/imag сравниваются строго; допуск gainDb — 0.001 дБ.
Отдельные физические сверки используют независимую binary64 комплексную сумму, не нормативные полиномы.
Клиентская синхронизация, реальный builder, медленная тень, миграция producer/Clone/receiver/seam/serialization
и фактические фрагменты речи остаются открытыми CT06/CT08/CT10, не засчитываются этим standalone kernel.

Авторский корпус DRAFT: **50** случаев, `oracle/vectors/channel_fading_v1.json`, LF SHA-256
`365e94e9c9a2386caae0a8b7e171471d84e615fabf4c14882347fb660ca46321`.
F27/F28/F29/F30 — host-only (bool вместо времени/веса, лишнее поле, пропущенное поле JSON);
остальные **46** предназначены для native, включая минимальный положительный binary32-вес F34.
Поддержка subnormal-арифметики Enforce пока не проверена: F34 — обязательный калибровочный случай,
его нельзя молча удалить/переименовать в host-only ради PASS. При расхождении нужен явный пересмотр численного
профиля и обработки underflow; физический сигнал не объявляется нулевым по отсутствию поддержки платформы.

Авторский CLI и 15 unit-тестов проходят; независимый checker и freeze **ещё не выполнены**.
