# Каталог прототипов раций — частичные паспортные данные

Версия 0.1, 2026-10-24, codex. **DRAFT / на независимое ревью**. Основание: owner Agora #4016,
ownership #4024/#4030. Это продолжение S2, но замороженный REQ-radio-device-adapter v0.2 не изменяется.

## Мини-intent

Игровому предмету нужен явный источник физических характеристик. Результат этого среза — каталог
«точный prefab → названный прототип/вариант → частичные паспортные факты» и исполняемый offline-поиск.
Названия и наследование берутся через штатный Workbench, параметры — из оригинальных руководств.
Core, сетевые binding, частоты, антенны и актуаторы не меняются. Каталог не создаёт готовый профиль S2.

## Контракт RC01–RC08

1. **RC01, идентичность.** Ключ — полный путь ресурса с `$ArmaReforger:` и версия установленной игры/Tools.
   Совпадения по basename, локализованному имени, подстроке, регистру или наследованию не выполняются.
   Каждая поддержанная вариация перечислена отдельно. Два базовых prefab учтены отдельно и не назначаются
   предметам как готовая модель. Это точное соответствие каталога, не проверка происхождения runtime-сущности:
   мод может переопределить ванильный ресурс; будущий серверный адаптер обязан проверять активные ресурсы.
2. **RC02, происхождение.** `sources` хранит вид, название, адрес и SHA-256 прочитанного файла/лога.
   Паспортные факты ссылаются только на `PRIMARY_MANUAL`, каждый имеет раздел/страницу и условия.
   UI-ключи и родители имеют `WORKBENCH_STATIC`; прежние таблицы игровых чисел имеют `REPO_REPORT`.
   SHA фиксирует использованный артефакт, не проверяет автоматически истинность его содержания.
3. **RC03, вариант.** R-148 и кандидат R-148E из FIA не сливаются: у них разные UI-ключи.
   Имена прототипов — сопоставление по проверенным именам ресурсов/UI-ключам, не подтверждение аппаратной
   эквивалентности. Поле `variant` обязательно и не заменяется произвольным значением по умолчанию.
4. **RC04, численные факты.** Единица записана в имени `quantity`. `value` — конечное положительное число;
   для `range` — пара включённых границ min ≤ max. Bool/строка/NaN/Inf не являются числами.
   `relation` различает `exact`, `specified`, `nominal`, `minimum`, `greater_than`, `maximum`, `less_than`, `range`.
   Условия обязательно сохраняются: режим мощности, напряжение, нагрузка, критерий чувствительности,
   доля каналов и исключения. Частотный интервал не означает возможность настройки на любую дробную частоту.
   Это исходные паспортные величины, а не округлённые binary32-входы ядра.
5. **RC05, неизвестность.** Отсутствие паспорта представляется пустым `facts` и явным списком `unknowns`.
   Нет подстановок 0 dBi, 0 dB NF или «типичной» мощности. Шаг каналов/полоса звука/полоса селективности
   не заменяют шумовую полосу. Микровольты не переводятся в dBm без определения напряжения и входного
   сопротивления; SINAD на аудиовыходе не становится требуемым входным SINR.
6. **RC06, данные игры.** `reportedGame` содержит сырые настройки отдельных трансиверов и ссылку на прежний
   отчёт. `tuningUnit=UNVERIFIED` сохраняется до Q-F. Наследованные, явные и не прочитанные поля различаются
   в `basis`; неизвестные численные поля равны null. Пустой список означает отсутствие прочитанных настроек,
   а не отсутствие трансиверов. Это не текущий снимок устройства и не паспорт.
7. **RC07, поиск.** `lookup(catalog, prefab, build)` сначала проверяет каталог; некорректный каталог вызывает
   `ValueError`. Затем: нестроковый/пустой prefab или build → `INVALID_INPUT`; другая версия →
   `BUILD_MISMATCH`; базовый prefab → `BASE_PREFAB`; отсутствующий точный ключ → `UNKNOWN_PREFAB`.
   Иначе результат `PASSPORT_PARTIAL` при наличии фактов или `IDENTITY_ONLY` при их отсутствии.
   Только эти два результата содержат независимые копии `binding` и `model`; входы не изменяются.
   Во всех результатах `readyForS2=false`. Загрузка JSON отвергает повторные ключи и нечисловые константы.
8. **RC08, проверка.** Уникальны ключи предметов, ссылки на модели/источники существуют, структура закрыта
   версией schema=1. Тесты покрывают все восемь предметов, базовые prefab, модовые/похожие имена, другую сборку,
   варианты, изменения результата без порчи каталога, невалидные поля/ссылки/значения и дубликаты JSON.

## Следующий этап

Независимое ревью каталога; недостающие руководства R-148/R-148E; затем отдельный контракт выбора рабочей
точки для S2, включая подтверждение частоты Q-F, текущий режим мощности, антенну, шумовую полосу и NF.
Расхождение игры и паспорта сохраняется как наблюдение, а не исправляется скрытым setter.

Проверка: `python -B oracle/radio_model_catalog.py --check`,
`python -B -m unittest discover -s oracle -p test_radio_model_catalog.py`.
