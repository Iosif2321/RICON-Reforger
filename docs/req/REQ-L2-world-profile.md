# REQ-L2-world-profile — поставщик профиля рельефа из мира (оболочка S1)

Версия: **0.3 DRAFT**, 2026-10-21. Автор: claude. Ревью codex: agora #2950, #2952, #2954, #2956 (учтены в v0.2),
#3055 (v0.3: граничные проверки обёртки `BaseWorld` в REQ-WP-01; геометрия, коды и векторы не менялись).
Основание: owner agora #2937 («ядро и оболочки для работоспособности»), #2935 (препятствия гасят сигнал),
разделение работ — agora #2946, #2952. Расширяет `REQ-L2-terrain.md` v0.6 §6, не меняя его правил.

Это requirements-артефакт. Он не доказывает поведение в игре: ни одна строка ниже не проверена в мире.

## Мини-intent

- **Проблема:** модель рельефа `RICON_TerrainDiffractionModel` уже считает дифракцию по профилю, но базовый
  поставщик профиля всегда отказывает (`RICON_TerrainDiffractionModel.c:175–190`). В игре холм между рациями
  пока ничего не меняет.
- **Результат:** поставщик, который строит профиль по правилу REQ-L2 §6 из **абстрактного источника высот**, и
  тонкая обёртка источника над `BaseWorld`. Чистая часть исполняется в Workbench без мира на синтетическом
  источнике; обёртка — только компиляция (`BLOCKED_NO_WORLD`).
- **Затронуто:** новый файл Enforce `RICON_WorldProfileProvider.c` (codex), эталон
  `oracle/world_profile_oracle.py` и векторы (claude). Модель, коды `RICON_EReason` и правило сетки не меняются.
- **Ограничения:** clean-room; без Play, мира и сервера; здания, деревья, материалы и вода — не S1.
- **Открыто:** что именно возвращает `GetSurfaceY` и его стоимость — только опытом в мире (§6).

## 1. API движка, на который опирается обёртка

Офлайн-документация Workbench, `EnfusionScriptAPI/html/interfaceBaseWorld.html` (уровень `DOC`):
`proto external float GetSurfaceY(float x, float z)`, строка 128, без описания. Онлайн-версия той же страницы
сигнатуру подтверждает (codex #2954). Оси: горизонталь — `x` и `z`, высота — `y`; так уже считает модель
(REQ-L2 §6). `IsOcean()` (строка 142) не принимает точку и говорит только о наличии океана на карте, поэтому
для профиля не используется (codex #2950).

## 2. Источник высот (seam)

**REQ-WP-01.** Поставщик не обращается к движку сам. Он получает источник высот с одной операцией:

`bool RICON_HeightSource.TryGetHeight(float x, float z, out float heightM)`

- базовый класс возвращает `false` (отказ), как базовый поставщик профиля;
- `RICON_BaseWorldHeightSource(BaseWorld world)`: при отсутствии `world` или нечисловых `x`, `z` — `false` без
  вызова API; иначе `GetSurfaceY(x, z)`; нечисловой результат — `false`, конечный — `heightM` и `true`. При
  `false` всегда `heightM = 0`. Эти проверки на границе не заменяют проверку в поставщике (REQ-WP-04): он
  повторяет её для любого источника, и источник может вернуть `true` с `NaN`, как синтетический (§4);
- синтетический источник для тестов (§4) реализует тот же контракт.

**REQ-WP-02. Вода — NOT_MODELLED.** Высота профиля — сырой результат источника. Вода, реки и озёра не
определяются и не подставляются; ε и σ из поверхности не выводятся (`WB-order-link-quality.md:42–43`). Риск этого
упрощения — §6.

## 3. Построение профиля

**REQ-WP-03. `RICON_WorldProfileProvider.GetProfile(query, config, out profile, out htg, out hrg)`** — сигнатура
базового поставщика. Любой отказ возвращает `TERRAIN_PROFILE_UNAVAILABLE`, при этом `profile = null`,
`htg = hrg = 0`. `OK` возвращается только с полным профилем и конечными высотами антенн. Шаги по порядку:

1. `query` или `config` отсутствуют, либо `config.IsValid()` ложно → отказ.
2. Источник отсутствует → отказ.
3. Любая компонента `tx` или `rx` (`x`, `y`, `z`) нечисловая → отказ.
4. `horizontalDistanceM = √((rx.x − tx.x)² + (rx.z − tx.z)²)`; сетка — **та же** функция
   `RICON_TerrainProfileSampling.BuildDistances` (REQ-L2 §6). Код не `OK` → отказ. Это включает `d > 500 км`,
   `n > maxProfilePoints` и `SKIP` (путь короче 2 м: модель обрабатывает его раньше, до поставщика он не доходит).
   Шаги 1–4 не обращаются к источнику.
5. Для `i = 0 … n−1` по порядку — точка выборки:
   - `i = 0` → ровно `(tx.x, tx.z)`; `i = n−1` → ровно `(rx.x, rx.z)`;
   - иначе `t = i / (n − 1)`, `x = tx.x + (rx.x − tx.x)·t`, `z = tx.z + (rx.z − tx.z)·t`.

   Один вызов `TryGetHeight` на точку. **Первая** неудача (`false` или нечисловая высота, REQ-WP-04) → отказ,
   дальше источник не опрашивается.
6. Профиль: пары `(d_i, h_i)`, `d_i` из шага 4 в км, `h_i` в м.
7. Высоты антенн над поверхностью: `htg = tx.y − h_0`, `hrg = rx.y − h_{n−1}`; нечисловое значение → отказ.
   Домены антенн `[0.01, 10000]` м и высот профиля `[−1000, 10000]` м поставщик **не** проверяет: это делает `L2`
   (`INVALID_ANTENNA_HEIGHT`, `INVALID_PROFILE`), модель переводит оба в `TERRAIN_PROFILE_UNAVAILABLE`
   (REQ-L2 §6). Правило одно, в одном месте.

Все отказы дают одну причину. Порядок шагов наблюдаем через число обращений к источнику, и векторы его
проверяют.

**REQ-WP-04. Нечисловые значения.** Проверка — `RICON_Num.IsFinite`. Выборка, вернувшая `true` с `NaN` или
`±Inf`, считается неудачной.

**REQ-WP-05. Стоимость.** Успешный вызов — ровно `n` обращений к источнику; кэша нет. Синтетический источник
считает обращения, векторы это проверяют: стоимость — часть контракта (нагрузка 30/60, PLAN Э10).

**REQ-WP-06. Где антенна.** Поставщик берёт позиции из `RICON_LinkQuery` как **точки антенн**. Перевод
«позиция носителя → точка антенны» (рост человека, мачта, машина) — дело адаптера устройства (S2). Если адаптер
передаст позицию ног, `htg ≈ 0` и `L2` откажет. Это ожидаемый fail-closed, а не повод занижать минимум 1 см.

## 4. Синтетический источник (TEST_ONLY)

Формула без интерполяции, одинаково вычислимая в Python и Enforce:

`height(x, z) = base + slopeX·x + slopeZ·z + Σ_k height_k · exp(−((x − x_k)² + (z − z_k)²) / (2·sigma_k²))`

- `failAtCall = k` — обращение номер `k` (с нуля) возвращает `false`;
- `nanAtCall = k` — обращение номер `k` возвращает `true` и `NaN`;
- счётчик `heightCalls` — число обращений.

Отказ задаётся номером обращения, а не областью координат, поэтому float32 и float64 не могут выбрать разные
исходы (codex #2954).

## 5. Векторы и приёмка

Файл `oracle/vectors/world_profile_v1.json`, эталон `oracle/world_profile_oracle.py`. Два уровня случаев:

- `level = "model"` — вызов модели целиком (`AppendLosses`). Ожидание: `modelReason`, `providerReason`
  (`NOT_CALLED`, если модель до поставщика не дошла), `heightCalls`; при успехе поставщика — `n`, профиль, `htg`,
  `hrg`, код `l2Code`; при `OK` модели — слои `fspl` (3D-расстояние, L0) и `terrain_diffraction` (`L` из
  `l2_terrain_oracle.l2`);
- `level = "provider"` — прямой вызов `GetProfile` на границах входа: `query`, `config`, источник отсутствуют,
  невалидный `config`, нечисловые компоненты позиций. Нечисловые числа в JSON записаны строками `"NaN"`,
  `"+Inf"`, `"-Inf"`.

| Test ID | Что проверяет |
|---|---|
| CT-WP-001 | ровная земля: профиль постоянный, `htg`, `hrg`, `L` совпадает с прямым вызовом `l2` |
| CT-WP-002 | направление и проекция: путь вдоль `x`, вдоль `z`, по диагонали, наклонная плоскость; обратный путь даёт обратный профиль |
| CT-WP-003 | холм между антеннами: `L` конечна, профиль повторяет холм. Знак «холм против ровного пути той же длины» только записывается: в векторах холм W05 даёт **меньше** потерь, чем ровный W06 (28.1 против 43.8 дБ, антенны 2 м, 50 МГц). Это эффект D-002, а не общий инвариант (codex #2956) |
| CT-WP-004 | дно ниже нуля: высоты берутся как есть, воды нет (REQ-WP-02) |
| CT-WP-005 | отказ и `NaN` на первом, среднем и последнем обращении: отказ, остановка на первой неудаче |
| CT-WP-006 | границы входа поставщика: null query/config/источник, невалидный config, нечисловые `x`, `y`, `z` у `tx` и `rx` — отказ без обращений |
| CT-WP-007 | `n > maxProfilePoints` и `d > 500 км`: отказ без обращений |
| CT-WP-008 | путь короче 2 м по горизонтали и частота вне домена: модель не вызывает поставщика |
| CT-WP-009 | антенна ниже поверхности и высота вне домена: поставщик `OK`, модель `TERRAIN_PROFILE_UNAVAILABLE` |
| CT-WP-010 | координаты масштаба карты (до 12 км от начала) — запас float32 |

**Допуски parity** (Enforce float32 против float64): `d_i` — `10⁻⁶·(1 + d)` км; `h_i`, `htg`, `hrg` — 0.01 м;
`L` и `fspl` — 0.05 дБ (как REQ-L2 §6). Коды и счётчики — точно.

## 6. Открытые вопросы

- Смысл `GetSurfaceY`: только рельеф или с объектами; что над водой — дно или поверхность; шаг сетки высот
  карты. Только опытом в мире (`BLOCKED_NO_WORLD`).
- **Риск воды (REQ-WP-02).** Если над морем `GetSurfaceY` возвращает дно, антенна лодки над дном −50 м получит
  `htg ≈ 52` м, и потери будут занижены. Решение — отдельное требование (охранник воды или морской режим) после
  опыта в мире, а не догадка в S1.
- Стоимость `n` вызовов на пару при 30/60 игроках — Э10, runtime.
- Один набор ε, σ на путь (REQ-L2 §2) — упрощение; D-008 остаётся.
