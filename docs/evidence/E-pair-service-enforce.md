## Реализация

`addons/RICON_Core/Scripts/Game/RICON/Core/RICON_PairService.c` содержит DTO передачи/слушателя/игрока/endpoint,
лимиты, вход, результат и службу без полей состояния. Она не меняет lifecycle, S2, менеджер, формулы или enum
`RICON_EReason`. Серверный вызывающий код должен обеспечить происхождение входов; подключения к PTT пока нет.

- Сначала полный preflight, только после него S2 и evaluator. Отказ: пустой результат и нулевые вызовы.
- Каждый входной массив ограничен 4096 элементами, кандидаты — 65536. Произведение вычисляется после проверки
  длин; время lease проверяется безопасной разностью после `now >= issuedAt`, без сложения сроков.
- Доступ и каталоги берутся из существующих `RICON_LifecycleDevice.CanAccess/Allows`. Устройства и трансиверы
  имеют разные таблицы; ключ endpoint — `(deviceId, index)`.
- Результат содержит все пары, включая отфильтрованные, по `(leaseId, rxDeviceId, rxIndex, rxPlayerId)`.
- `BuildQuery` вызывает настоящий S2; бюджет считается существующим evaluator и копируется в результат значениями.
  Защита при нарушении обещания evaluator «никогда null»: EVALUATED с невалидным бюджетом NUMERIC_FAILURE.
  Это защитное расширение сверх REQ, проверяемое отдельным сценарием; для соблюдающего интерфейс evaluator
  поведение не меняется. Конечность чисел обычного бюджета опирается на контракт evaluator REQ-LE-81;
  служба не повторяет его числовую валидацию (ревью claude #3216).
- Идентификаторы lease допускают int.MAX по lifecycle; идентификаторы endpoint используют домены S2.
- Сортировка слушателей вставками ограничена 4096; стоимость на 30/60 игроках требует измерений Э10.

## Фикстуры и контроль стенда

`gen_pair_service_fixture.py` закреплён по SHA и копирует ожидания из JSON. Использует генераторные литералы S2.
Сгенерированный `RICON_PairServiceFixtures.c` — только тестовые данные, без пересчёта ожидаемого результата.
Типизированное представление C18: неизвестное строковое состояние `ALIVE` отображается в невалидный enum `-1`;
это одна явная адаптация представления, исход по-прежнему INVALID_ELEMENT. `hasEvaluator` допускает только bool.

`RICON_PairServiceFixtureSupport.c` проверяет:

- 72 результата вызова и **260 записей пар**: все поля, порядок, закрытые коды, флаги и бюджет;
- каждый счётчик против настоящей обёртки: S2 через переопределение счётчика плюс `super.BuildQuery`, evaluator
  через передачу тому же настоящему `RICON_WirelessLinkEvaluator`; ожидание не подставляется;
- неизменность значений и порядка всех входов, включая вложенную политику и RF-параметры; повторный вызов после
  искажения первого выхода даёт новые результат, массив и записи;
- 15 отрицательных контролей сравнения: null, лишняя/пропущенная пара, перестановка, оба счётчика ±1,
  другая ветвь pairCode, SINR вне допуска, неверный/NaN Q, другой endpoint, флаг бюджета и код вызова;
- четыре дополнительные проверки: перестановка пяти массивов P01; пустая матрица; null входа; защита от null
  бюджета нарушившего интерфейс evaluator. При пустом/недопустимом входе фактических вычислений нет.

Для валидного бюджета допуск SINR **0.05 дБ**, Q **0.002**. Числа обязаны быть конечны; неактивные и невалидные
бюджетные поля сравниваются точно. Генератор: **8 unit-тестов PASS**; эталон S3: **15 unit-тестов PASS**.

## Границы

- Это чистый расчёт на синтетическом серверном состоянии. Настоящие lifecycle/PTT → binding DTO, список
  слушателей, данные радиокомпонентов, карта и порядок игровых callbacks здесь не проверены.
- Один context/evaluator на вызов; взаимные помехи и захват канала не моделируются, помеха задаётся контекстом.
- LinkId, linkSeq, снимки, маршрут и TTL публикации — S3b через существующий менеджер.
- Доставка голоса и управление звуком отсутствуют: BLOCKED_NO_ACTUATOR; игровой приёмки и измерений нагрузки нет.
