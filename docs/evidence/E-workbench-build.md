## Предлагаемая команда проверки компиляции (не выполнялась)

```bat
"C:\Program Files (x86)\Steam\steamapps\common\Arma Reforger Tools\Workbench\ArmaReforgerWorkbenchSteamDiag.exe" ^
  -gproj "C:\Users\Ded\Documents\Projects\ARMA 3 Scripts\RICON-Reforger\addons\RICON_Core\addon.gproj" ^
  -wbModule=ScriptEditor -validate -wbSilent -noThrow ^
  -logLevel warning -logsDir ricon-validate -log-scr-checksum
echo exit=%ERRORLEVEL%
```

Критерий `WORKBENCH_COMPILE_PASS`: код возврата `0` **и** в логе нет ошибок компиляции скриптов, а
`-log-scr-checksum` перечисляет файлы `Scripts/Game/RICON/**`.

## Чего документация не говорит (НЕ НАЙДЕНО)

1. Нужен ли `-run` после `-wbModule=ScriptEditor` для `-validate` (для других модулей — «You need to include -run
   after each instance of -wbmodule»).
2. Сочетаются ли `-wbSilent` и `-validate`, и какой код возврата тогда приходит.
3. Находит ли Workbench базовую игру по зависимости `58D0FB3206B6F859` из `addon.gproj` сам или нужен
   `-addonsDir` с папкой `Arma Reforger\addons`.
4. Куда именно пишется лог (`<PROFILE_PATH>/logs/<NAME>` — путь профиля Workbench не указан).
5. Отличается ли поведение `ArmaReforgerWorkbenchSteamDiag.exe` от `ArmaReforgerWorkbench.exe` из примеров.

Эти пункты закрывает только первый реальный запуск.

## Кто запускает

Решение владельца №3: Workbench-сессии проводит ассистент владельца; агенты Workbench не запускают — в том
числе headless: `-wbSilent -validate` тоже запускает Tools. Поэтому команда выше передаётся **исполнителю
заказа `[Workbench]` №001** как уточнение к пункту 10 (`WB-order-001.md`). Агенты её не запускают до нового
прямого решения владельца. Цикл «правка → компиляция» не блокируется: после каждой пачки правок ассистент
повторяет ту же проверку по заказу (поправка codex id440).
