# Интеграция RICON со штатным радио — изменения 2026-11-04

Статус: **КОД ПРИМЕНЁН; КОМПИЛЯЦИЯ МОДУЛЕЙ ПОДТВЕРЖДЕНА ЖУРНАЛОМ; ПЕРЕДАЧА НЕ ПРОВЕРЕНА**. После компиляции Workbench завершился с ошибкой Steam, поэтому общий процесс не получил PASS. Полная интеграция player VoN остаётся незавершённой: `NO_SUPPORTED_PAIR_HOOK`. Общая программа 0–8 не завершена.

## Что изменено

Goal проекта `.opencode/goal/{state.json,plan.md,log.md}` переведён в текущую фазу реализации. Исходная общая цель, прежние поля и история сохранены. `complete=false`. Машинная карточка Goal чата отдельно продолжает возвращать `paused`; доступные инструменты не позволяют изменить её objective или выполнить resume. Подмена карточки новой или ложное завершение не выполнялись.

В основной проект перенесены ранее проверенные `RICON_LivePairShadow.c` и дополнение `RICON_LiveNativeRxGame.c`. Точный код уже присутствует в canonical `tools/RICON_LiveProbe/Scripts/Game/RICON_Live/`; сравнение байтов после переноса прошло. Мост читает настоящие actor/radio/transceiver observations и вызывает существующие PairService и WirelessLinkEvaluator. Выбор индекс0, RF-профиль, lifecycle DTO и разрешения здесь явно TEST_ONLY. Это диагностическая интеграция расчёта, а не управляющий порт голоса. Она включается только явным `-riconPairShadow=1` вместе с условиями существующего NRX-режима, ограничена по времени/числу вызовов и очищается при завершении мира.

Существующий `RICON_LiveGenericRadioProbe.c` расширен и применён к canonical после независимого source review. Новый режим `-riconGenericPair=1` использует уже существующий generic bench; сам флаг ничего не запускает. Без него прежние положительный, частотный, TX-model-LOST и recovery контроли сохраняются.

В новом режиме сообщение всегда отправляется через штатный `BeginTransmission`, включая случай, в котором RICON должен получить valid MODEL_LOST. `OnDelivery` сначала сохраняет прежние raw callbacks/counters, затем отдельный обработчик читает реальные текущие TX/RX observations и вызывает настоящий PairService. Только допустимая строка конкретного RX разрешает фиксированное информационное действие `GENERIC_PAIR_INFO_V1`. Предусмотрены четыре попытки allow → valid MODEL_LOST/deny → recovery → allow. Нативное качество и состояния устройств этот обработчик не перезаписывает.

Это **одно принимающее устройство в одном игровом мире, без сериализованной сетевой полезной нагрузки**. Профили, lease/epoch/IDs и generation — явно TEST_ONLY. Независимость A/B/C, authority реальных игроков, cross-process доставка и голос этим кодом не квалифицированы. Тестовая мощность −200 dBm меняет только вход модели, не параметры игровой рации. Проверяются точные native refs/index/catalog/world, питание/mute/tuning/keys, действительность результата, повторы, TTL2500ms и состояние после вычисления; новый режим ограничен четырьмя попытками/20s, receipts закрываются при terminal/Stop.

Изменены три исходника LiveProbe: новый `RICON_LivePairShadow.c`, lifecycle hook `RICON_LiveNativeRxGame.c` и расширение `RICON_LiveGenericRadioProbe.c`. Production Core и его голосовая граница не изменены.

## Что пока нельзя назвать работающей голосовой интеграцией

Для голоса нужен серверный порт, который привязывает подтверждённого отправителя к его передающей рации, принимает список радиополучателей RICON и конечное качество до объединения с обычной речью. Доказанная машинным кодом точка не раскрыта проверенным скриптовым API. Частные адреса, проект предлагаемого метода и возможность зарегистрировать собственную C++ функцию не дают такого доступа автоматически.

Поэтому `RICON_VoNIntegration.ApplySnapshot` по-прежнему возвращает `BLOCKED_NO_ACTUATOR`. Production-калибровка разборчивости остаётся `BLOCKED_CALIBRATION`. Установка расширения, изменение бинарников, второй голосовой транспорт и обход штатных разрешений не выполнялись. Данные мира, жизненный цикл игроков, независимость трёх участников, фактическое качество звука и нагрузка требуют отдельных незакрытых испытаний.

Собственные generic radio messages и microphone VoN — разные native пути. Полезное действие из OnDelivery собственного сообщения нельзя выдавать за фильтрацию обычного голоса, защиту секретной полезной нагрузки или добавление маршрутов за пределами штатного радио-графа.

## Разрешённая компиляция Script Editor

После прямого ответа владельца «Разрешаю только компиляцию в Script Editor» root выполнил один процесс Workbench с отдельными profile/logs, `-wbModule=ScriptEditor`, `-noBackend`, `-exitAfterInit`, без `-plugin` и параметров запуска мира. Первая проверка допуска ещё до запуска отказала из-за избыточного нового порога8GiB. Порог уточнён по существующему single-ScriptEditor runner: его допуск2.5GiB; здесь оставлен запас4GiB и аварийное завершение ниже2GiB commit. Это не изменение pagefile или пользовательских программ.

Compiler input содержит CRC-строки всех трёх целевых исходников. Журнал подтверждает завершённые модули Game (5764files,11589classes) и WorkbenchGame (192files,637classes), `SCRIPT(E)=0`, компиляция Game3962.5874ms. Все59 source hashes до/после совпали; независимый reviewer подтвердил эти факты и отсутствие runtime-маркеров fixture.

Сразу **после** module summaries платформа сообщила `SteamAPI_Init failed` и завершилась с exit−1. Поэтому точный результат — `ENFORCE_MODULE_COMPILE_LOG_CONFIRMED_PLATFORM_INIT_FAILED`, `overallProcessPass=false`. Первичная platform-ошибка и последующие resource-leak shutdown сообщения сохранены; ошибок нового скриптового кода не выявлено. Процесс завершён. Наличие классов/fixture names в CRC-списке не означает их запуск. Повторная компиляция без изменения исходников не требуется; game/runtime и функциональная интеграция не квалифицированы.

Дополнительный узкий static probe трёх функций аудио установил provider contract `AudioSourceTemplate → ProjectSignal/ProjectVariable → runtime graph`. Произвольный sender SignalsManager→private VoN binding всё ещё OPEN; нового управляющего API из этого результата не следует. Private functions/RTTI не стали Workshop hook.

## Откат и продолжение

До изменений сохранены исходные версии. `shadow/transfer.py rollback` восстанавливает прежний hook и удаляет только добавленный helper, предварительно проверив, что после применения их никто не менял. Если generic-обработчик уже использует helper, сначала требуется вернуть его исходную версию. Подготовительные READY/access отчёты описывают состояние до root apply; актуальное наличие файлов определяется apply/verify receipts.

Ближайший незакрытый результат для полной цели — реальный поддерживаемый серверный доступ к radio population/final-q порту. Компиляция модулей наблюдалась; actual native проверка добавленного кода и голосовой actuator не пройдены. Последний допуск владельца ограничен Script Editor: Play, сервер и передача остаются вне него.
