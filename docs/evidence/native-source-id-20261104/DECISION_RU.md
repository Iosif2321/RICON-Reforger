# Проверка защищённого carrier-варианта для native VoN

2026-11-04. **HYPOTHESIS_REJECTED_FOR_AUTHORITATIVE_VON / STATIC_CODE_ONLY.** Полная цель — управление RICON радиополучателями и качеством обычного голоса с сохранением DIRECT и остальных пар. Она остаётся незавершённой и активной.

## Что проверялось

Вместо повторения прежнего отрицательного API-поиска проверена новая гипотеза: внутренние передатчики остаются server-owned и скрыты от чужих клиентов, а обычные RX leaves имеют source range=1 и расположены дальше1m друг от друга. Могло ли это закрыть подстановку источника без DLL и изменения бинарника?

Публичный `RplComponent.EnableStreamingConNode` действительно предоставляет per-player управление streaming; документация ограничивает его Network Dynamic Simulation. [Официальный интерфейс BI](https://community.bistudio.com/wikidata/external-data/arma-reforger/ArmaReforgerScriptAPIPublic/interfaceRplComponent.html). В наличии метода и его установленной декларации нет гарантии авторизации radio ID внутри голосового сообщения.

## Новое доказательство и решение

**Гипотеза не закрывает доверие к источнику.** Контекст VoN читается как raw192bits/24B. Radio ID в+0C не проходит peer-local remap. Сервер разрешает его через общие банки replication ID с проверками границ/живой записи/типа, без сравнения с исходным peer или streaming. Поэтому известный ID живой server-owned рации не отвергается этой цепочкой из-за отсутствия её replica у отправителя. Calling-VoN owner check относится к другому объекту. Это не утверждение о прохождении остальных radio gates или о продемонстрированной эксплуатации.

Полная цепочка и восемь bounded listings: [raw decode → global lookup](rpl-source/PROOF_RU.md). Она снимает конкретную неизвестность: не является ли source radio ID защищённой per-peer reference. Скрытие/сложность получения ID не заменяет проверку права на источник.

Условная RF-изоляция RX leaf работает только для прямого перехода при неизменных source range/position/type. Range destination не расширяет source. Но relay в пределах первого метра может продолжить маршрут со своей большей дальностью. [Доказательство и relay-контрпример](carrier-authority/RESULT_RU.md).

Уточнён также scope `SetRange`: проверенное тело пишет локальное значение без отдельного owner/proxy guard. Документированное owner/server действие не является доказательством запрета proxy-local записи. Из этого не следует возможность изменить серверную authoritative копию: сетевой путь требует своего доказательства. Исторические DOC-срезы сохраняются с этой поправкой; универсальная неизменяемость server range не заявляется.

**Carrier adapter не создаётся:** даже решение проблемы собственного RX не устраняет независимый выбор настоящего чужого TX по raw ID. Интеграция, которая держится только на скрытии таких ID, не соответствует текущей цели.

## Текущая граница реализации

Три ранее внесённых source и результат компиляции не изменялись. Generic diagnostic не повышен до voice actuator. `ApplySnapshot = BLOCKED_NO_ACTUATOR`, production calibration открыта. Для полной архитектуры по-прежнему необходим проверенный серверный механизм exact sender→TX authorization и формирования radio population/final quality до overlay. Его отсутствие нельзя компенсировать ещё одним control RPC, глобальным mute или статусом APPLIED.

Текущие разрешения допускают source/static работу и только компиляцию Script Editor. Play/server/capture, binary patches, DLL install, pagefile changes и закрытие других приложений исключены. Этот проход не запускал даже компилятор: уже подтверждённая компиляция не повторялась. Машинный Goal теперь active; прежние paused/null snapshots — история.

Следующий результат должен давать сам доступ к недостающему voice policy механизму. Повторные скрытые carrier spawn/UI/нагрузочные прототипы не имеют основания после отрицательной квалификации. Функциональная приёмка A/B/C и DIRECT остаётся обязательной и не выполненной; цель не объявляется завершённой.
