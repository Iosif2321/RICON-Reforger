**ACCEPT — WITH_RAW_DECODE_AND_GLOBAL_LOOKUP, с отдельным условным RF-контрактом.** Проверяющий `codex.goal.review`; только чтение source proofs,15 закреплённых ASM artifacts и семи необходимых frozen joins. Текущий EXE SHA256 `1d221a990fa16c78fe02f685a7ba1330be115ca93cd3b641e67e5d3f1b40d9c9` совпал. Все8 hashes rpl-source receipt и7 hashes carrier evidence совпали; hash carrier RESULT также совпал. Движок/SDK/Ghidra, exploit/packet операции и новые targets не запускались; чужие файлы не менялись.

Raw192-bit read at29F691/29F69C,24B intermediate transfer at29F6AE и24B injection29FF63 сохраняют opaque context, включая поле+C. Полный bit reader выполняет bounds/cursor/mask/copy, а не peer-local reference conversion. В реальном Send `2A0CDF MOV ECX,[R14+C] →2A0CE3 CALL5DD350`. Проверенная цепь `5DD350→11C6A10→846FC0→DAA9B0` берёт ID через global manager142177B60, high2bit bank/low30bit slot и local slot validity. В ней нет sourcePeer, owner-radio comparison или streaming map. Тип/живой slot/entity/radio и transceiver index остаются обязательными условиями.

Поэтому гипотеза **«server-owned hidden TX_C нельзя выбрать именно потому, что он не streamed/не owned вызывающим peer» опровергнута на этой reference-resolution цепи**, если его live valid ID уже известен и выбран допустимый index/mode. Это не доказательство получения неизвестного ID и не доказательство прохождения всех остальных gates или реальной передачи голоса. Owner admission **calling VoN replicated node** atE67F66..71 сохранён; его нельзя перенести на raw radio ID внутри аргумента. Последующие RF/key/frequency/power, Social и recipient gates тоже не отменены. Blanket vulnerability, remote exploit и общий authority bypass не заявлены.

Secondary RF proof принят с его предпосылками: ordinary source range+40 читается at5E24F6/5E25BF и сравнивается с3D distance² at5E25DD..E0. При sourceR=1 и d>1 прямое ребро не включается; дальность destination не делает ребро симметричным. Equality допускается, q=0 не равен hard reject. Но matched-key reachable Relay проходит expansion slot5 at5DF94A, использует собственный source range at5E2B98 и допускает следующий hop. Контрпример S0,R0.5,B10 при ranges1/65535/1 проходит оба hops. Следовательно leaf range ограничивает первое ребро, не суммарную reachability. Нужны реальные server origins/classes/topology/cache-state; обычный нерасширяемый TX не превращён предположением в relay.

SetRange local body действительно пишет transceiver+40 at5E046B без local role guard. Это допускает proxy-local изменение; **не устанавливает remote authoritative instance write**. CommonSync Broadcast submit и client-role classifier не доказывают C→S queue path: Broadcast3/client0 здесь не выбирает queue2. Incoming calling-node owner gate остаётся отдельным. Нет оснований ни объявлять blanket bypass, ни доказывать неизменность server range одним API-комментарием.
