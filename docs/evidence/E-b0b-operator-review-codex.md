# B0b: независимое ревью операторских скриптов

Дата: 2026-10-25. Автор: codex. Работа с claude в Agora, продолжение после B0a.
Охват: `tools/RICON_LiveProbe/ops/`; код принадлежит claude, замечания и независимые
контрпримеры — codex. Этот документ не является приёмкой сетевого сервера.

## Исправленные границы

| Проверка | Найдено | Исправление / уровень проверки |
|---|---|---|
| Владение процессами | Старый tracked PID мог указывать на другой процесс; пустой tracked исключал сам Workbench из teardown. | Удерживаемые Process handles, root отдельно от tracked, finally. Симуляция старой выборки и пять чистых проверок исправленных функций выполнены codex. |
| Время создания процесса | Допуск 0.5 с мог принять другой экземпляр. | Сравнение UTC ticks с усечением до микросекунды через целочисленный остаток; 100 мс и следующая микросекунда отвергаются. На собственном процессе измерена разница CIM/.NET в 9 тиков по 100 нс. |
| Watchdog | Проверка StartTime без удержания Handle оставляла разрыв перед Kill. | Handle берётся до сравнения; для двух .NET-значений — точное равенство ticks. Source проверен после ba1835b. |
| Переходные окна | Проверка с первой секунды останавливала штатную загрузку на двух известных заголовках. | Только пассивное ожидание точных заголовков собственного PID, пока нет World Editor и прошло не более 30 с; глобальный список известных рабочих окон не расширен. Четыре чистых контроля повторены codex. |
| Вывод PowerShell | Строки ExpandRead попадали в возвращаемое значение и могли скрыть false. | Диагностика через Write-Host, единственный bool; закрытие принимается только при Collapsed, не PartiallyExpanded. |
| Неполный снимок настроек | Пропавшее чтение target приводило к восстановительному Toggle из неизвестного состояния. | Полный набор ключей и только On/Off; независимый mock без UI подтвердил STATE1_READ_FAILED после одного переключения вместо второго слепого действия. |

Самопроверки WPF/UIA выполняет оператор claude. Codex самостоятельно выполнял
только чистые функции и контрпримеры со stub-объектами, без UI Automation и без
реальных Kill. Числа тестов автора не выдаются за отдельный UI-прогон Codex.

`b436a390de0887be41afc7e314ec9b53c94787823fd016b492b03c299cc52d1e`:
OPEN_ONLY saved=0 isGameMode=0, 0 SCRIPT(E), нет PLAY_REQUESTED и ENDPOINT_START.

В UIA-выводе собственного окна World Editor наблюдался путь
`Game → Play Game Options → Server localhost`: пункт enabled=True, Toggle=Off.
Соседний `Server localhost + PeerTool` также Off. Оба раскрытых уровня закрылись
в Collapsed, изменения реестра и профиля не обнаружены. Принято как **UI_OBSERVED**.
Соответствие этому пути аргумента ExecuteAction не проверялось.

## Обратимое переключение

Квитанция [двух опытов](receipts/b0b-toggle-roundtrip-claude-20261025.txt),
коммит b6eddbc, проверена codex (#4696). SHA исходных console.log совпали:

- TogglePattern, `122839`: `c018f608c356870943c37ecd081aba1afe3ac4155619bead5cfa8c15302a08bf`.
  Один вызов не изменил настройку: TOGGLE_NO_EFFECT, исходное состояние сохранено.
- InvokePattern, `124042`: `4d3f22e7cf208715944498ffa0a1b40ac54a8c49a059b06d68720bc258425f54`.
  Два действия дали Off → On → Off; остальные девять пунктов не менялись.

В обоих исходных логах codex независимо проверил SCRIPT(E)=0, один OPEN_ONLY
с isGameMode=0, отсутствие PLAY_REQUESTED/ENDPOINT_START. Полные UI-снимки,
отсутствие новых процессов и равенство реестра/профиля до и после — наблюдения
оператора claude в квитанции, а не отдельный UI-прогон codex. Уровень UI_OBSERVED.
Позднейшие серверные опыты и отдельное чтение Off после первого из них описаны
в [журнале сетевого режима](E-b0b-network-mode-codex.md). Начало Listen подтверждено,
полный цикл наблюдения и подключение клиента не приняты.

## Подготовка A2 после двух блокировок UIA

Вызов UI Play заменён сигналом-файлом и SwitchToGameMode в launcher. Встречное
ревью launcher — #4748, итоговой операторской части — #4761. Коммиты 4a0589d,
8c609d5, b73cff6 и f8cc4f7. Новый Play по сигналу ещё не выполнялся.

Найдены и исправлены два случая частичного успеха:

- После вызова Invoke ошибка проверки меню не означает, что Play не начался.
  Признак попытки запрещает преждевременное восстановление настройки.
- После успешного CreateNew файл уже виден launcher. Ошибка Close не сбрасывает
  признак возможного запуска; made устанавливается только успешным Open.
  Наличие файла после неуспешного Open не доказывает владение им.

На фактической NewStartFlag из f8cc4f7 codex независимо выполнил четыре проверки
без UI: новый файл; существующий файл с сохранением содержимого; ошибка Close
с освобождением handle; неверный путь. Все четыре прошли. SHA библиотеки:
`4033ffbd0fdd2fa78c7a499f9a3d0ba116db637f347f250c52b36cfb4e305bb2`;
SHA runner: `51b63e6124dcf7f39c139c06c40d770978d14b62e5ebe2ea3694a914a8a61e27`.
Самопроверка WPF 196/196 на b73cff6 и прозрачность тестовых Popup — результат оператора;
codex не запускал эти графические проверки.

После просьбы владельца убрать всплывающие тестовые меню следующий видимый
Workbench ожидает ответа на отдельный вопрос claude #4760. Готовность A2
по исходникам и компиляции не означает успешный серверный опыт или проверку звука.
