## Что подтверждено в игре

Штатный WbReader в ScriptEditor, без мира/Play/сервера. Игра и Tools: **1.8.0.13**, версии обоих exe прочитаны.
В корне `$ArmaReforger:Prefabs/Items/Equipment/Radios/` десять файлов; все открыты в двух успешных поисках.
Получены пути/родители и семь явных UI-ключей. Локализованный текст названия не читался; связь с реальным
прототипом — явное сопоставление по ключу/имени ресурса, а не доказательство одинаковой аппаратуры.

| Предмет, путь после корня | Кандидат прототипа | Основание имени |
|---|---|---|
| Radio_ANPRC68.et | AN/PRC-68 | собственный ключ ANPRC68, строка 27 |
| Radio_ANPRC77.et | AN/PRC-77 | Deployable_Base:36 через проверенного родителя |
| Radio_ANPRC77_COK.et | AN/PRC-77, игровой COK | через ANPRC77 и Deployable_Base; смысл суффикса не угадывается |
| Radio_R107M.et | Р-107М | собственный ключ R107M, строка 28 |
| Radio_R107M_FIA.et | Р-107М, игровой FIA | собственный ключ R107M, строка 27; эквивалентность аппаратуры не доказана |
| Radio_R148.et | Р-148, паспорт пока неизвестен | собственный ключ R148, строка 26 |
| Radio_R148_FIA.et | отдельный кандидат R-148E | собственный ключ R148E, строка 26; параметры Р-148 не копируются |
| Radio_RF10/Radio_RF10.et | RF-10 | Radio_RF10_base:35 через проверенного родителя |

Deployable_Base и Radio_RF10_base записаны как базовые prefab, не как готовые предметы.
Точные ключи и источники сохранены в JSON. Произвольные наследники, совпадение basename и переопределения модами
не разрешаются автоматически: будущему runtime-адаптеру нужна проверка активного ресурса.

  лимит 15 строк не достигнут, SCRIPT(E)=0. Полные SHA находятся в `sources` каталога.
- Промежуточный `…catalog-names…-053408`: поиск `Name` достиг лимита и охватил только три файла;
  полноту не подтверждает. Первый запуск в sandbox `…053250` завершился exit −1; логи обнаружены в рабочем
  каталоге и перенесены в собственную временную папку. Этот запуск не используется как доказательство.

Сырые диапазоны/шаги в `reportedGame` взяты из прежнего `E-radio-data-wb.md` §2 с фиксацией его SHA и уровнем
`REPO_REPORT`; эти численные поля сегодня не перепроверялись. Наследование в отчёте и явные значения различены.
Например, у RF10 там указаны диапазоны 30000–76000 и 20000–52000, но паспортная полоса другая. Значения не
исправляются, единица getter остаётся `UNVERIFIED`. Пустой список настроек означает отсутствие данных.

## Паспортные источники

Скачаны только документы во временную папку `ricon-radio-catalog-codex-20261024`; архивы игры и DLL не трогались.
Страницы отрисованы Windows PDF API и просмотрены как изображения; таблицы не приняты только по OCR.
Оригиналы размещены на зеркалах; авторство руководств установлено по самим документам. SHA закреплены в каталоге.

| Руководство | Просмотренные страницы | Что перенесено |
|---|---|---|
| [AN/PRC-68, TM 11-5820-882-23](https://radionerds.com/images/2/2a/TM_11-5820-882-23.pdf) | 1-1, 1-2; PDF 8–9 с нуля | 30–79.95 МГц; сетка 50 кГц отдельно от предустановок 200 кГц; минимум 1 Вт; 0.5 мкВ при 10 дБ SINAD |
| [AN/PRC-77, TM 11-5820-667-12](https://www.radionerds.com/images/8/8a/TM_11-5820-667-12.pdf) | 1-2, 1-3; PDF 13–14 | два поддиапазона до 75.95 МГц, сетка 50 кГц, интервал мощности 1–4 Вт, две штатные длины антенн |
| [Р-107М, 1.000.023 ТО, 1977](https://www.radiomanual.info/schemi/Surplus_EstEurope/R-107M_serv_1977.pdf) | 6–9; PDF 3–4, развороты | 20–52 МГц, отсчёт 1 кГц, режимы минимум 1/5 Вт при 7.2 В на 75 ± 1 Ом; чувствительность не хуже 1.5 мкВ при указанном отношении выходных напряжений |
| [RF-10, Spoj-21-57/1, 1977](https://www.vu9967.cz/files/technika/rf-10/spoj_21-57-1_rf-10_technicky_popis_1_dil.pdf) | 5–7; PDF 2–3 | 44–53.975 МГц, сетка 25 кГц; номинал и нижние ограничения мощности при 5/6 В; чувствительность при 12 дБ SINAD с исключениями по каналам |

RF-10: предел лучше 0.5 мкВ гарантирован минимум для 97.5% каналов; допускается до 1 мкВ для восьми и до 2 мкВ
для двух каналов. Поэтому один универсальный порог по краткому веб-описанию не принят. Для Р-107М критерий
«10:1 по выходному напряжению» не превращён в 10 дБ входного SINR. Сопротивление нагрузки передатчика не
объявлено входным сопротивлением приёмника. Длина антенны не превращена в 0 dBi или другую догадку.

По ревью Claude #4055 добавлены дальности PRC68/77 и RF10 с условиями, полуинтервалы избирательности PRC68,
ПЧ Р-107М и подавление соседних каналов Р-107М/RF10. Это справочные наблюдения для будущей проверки сценариев,
а не готовые пороги: неопределённая паспортная местность не позволяет требовать точного совпадения расчёта.

Оригинальный архив Р-148 найден на [странице документа](https://www.radioscanner.ru/files/military/file18575/),
но загрузка не прошла проверку TLS, содержимое не прочитано. Числа из вторичных описаний не перенесены.
Для варианта E отдельного первичного документа пока нет.

## Проверка и ограничения

`python -B -X utf8 oracle/radio_model_catalog.py --check` → `RADIO_MODEL_CATALOG_PASS models=6 bindings=8`.
`python -B -X utf8 -m unittest discover -s oracle -p test_radio_model_catalog.py` → **11/11 PASS**.
Отрицательные случаи включают дубликаты JSON/предметов, неизвестные ссылки, bool/NaN/Inf, очень большое целое,
перевёрнутые диапазоны, ложную единицу native tuning, похожие имена модовых предметов и другую версию игры.
Тест большого целого обнаружил `OverflowError` внутри `math.isfinite`; исправлено единым отказом валидатора,
повтор десяти тестов PASS. Проверены неизменность каталога и отдельные копии результата.

Пример в PowerShell:

```powershell
python -B -X utf8 oracle/radio_model_catalog.py --prefab '$ArmaReforger:Prefabs/Items/Equipment/Radios/Radio_ANPRC68.et' --build 1.8.0.13
```

Любой результат содержит `readyForS2=false`. Поиск не обращается к игре, не меняет настройки и не создаёт
`RICON_RadioRfProfile`. Требуются отдельные выбор рабочей точки, шумовая полоса/NF, антенна, определение
чувствительности, подтверждение tuning и серверного binding. Частичный offline-каталог прошёл взаимное ревью;
интеграция в S2 и проверка игровых RF-характеристик остаются открытыми.
