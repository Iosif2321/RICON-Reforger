# B0a: наблюдатель локальной роли в игровом объекте

Дата: 2026-10-24, обновлено 2026-10-25. Автор: codex. План согласован claude #4563/#4568;
source-review реализации и дополнений принят claude #4574/#4577/#4582.
Gate-off и один включённый цикл наблюдались в Play; повторный запуск ещё проверяется.
Статус: **COMPILE_PASS, GATE_OFF/ON_OBSERVED, RESTART_RETEST_PENDING**. Это продолжение
[плана локального peer](../plan/LIVE-peer-local-plan-codex.md).

## Изменение

Проблема: временная сущность старого launcher-а не доказывает наличие наблюдателя
у отдельного клиента. Поэтому добавлен Game-side вход, доступный независимо
от существования такой сущности.

- `RICON_LiveEndpointGame.c`: modded ArmaReforgerScripted; запуск после успешного
  super.OnGameStart, опрос после super.OnUpdate, завершение перед штатными
  OnGameEnd/OnBeforeWorldCleanup. Каждый override вызывает super ровно один раз.
- `RICON_LiveEndpointProbe.c`: собственные Journal и существующий RadioReader;
  30 срезов не чаще одного в секунду игрового времени, учёт смены локальной
  привязки, полное завершение и освобождение ссылок.
- `PlayerState()` в стенде стал публичным static helper; его тело и формат сохранены.
- Launcher с `-riconBenchMode=endpoint` пропускает старый bench. Без дополнительных
  запросов GameMode/RadioManager он не создаёт сущности и не открывает действие редактора.

Единственное значение, включающее наблюдатель, — `-riconEndpointProbe=1`.
Без него не создаются Journal/RadioReader и не добавляются события наблюдателя.
Этот путь не подписывается на VoN, не использует callqueue и не меняет рации,
персонажей, физику или сетевые свойства. Проверка этих свойств в Play ещё впереди.

## Основание и компиляция

[Квитанция чтения Game/game.c](receipts/endpoint-bootstrap-source-codex.json):
8 коротких поисков, каждый не более 15 строк. Один точный поиск cleanup дал ноль
совпадений: его декларация содержит `override protected void`, что выяснилось
по более широкому поиску. Header 20–34 подтвердил отсутствие атрибута класса.
Исходный ArmaReforgerScripted живёт весь процесс; cleanup вызывается отдельно от
его уничтожения. Source CRC game.c — 973eae69.

[Квитанция компиляции](receipts/endpoint-bootstrap-compile-codex.json) сохраняет
неудачный первый прогон и последующие исправленные снимки. Первоначальная ошибка: имя аргумента
override должно совпадать с прототипом (`timeslice`, не `timeSlice`). Финальный
прогон после исправления ожидания редактора — `ricon-endpoint-compile-codex-20261025-000708`:
0 SCRIPT(E), source-stable, существующая текстовая проба 15/15. CRC и снимок SHA
всех 18 файлов LiveProbe — в квитанции; Game bootstrap и Probe не менялись при этой правке.

Текстовая проба проверяет кодек, а не жизненный цикл bootstrap. Этими компиляциями
мир и клиент не запускались; отдельные игровые прогоны выполняет оператор claude.

## Формат ENDPOINT-событий для независимого разбора

Используется прежняя оболочка RICON_LIVE: seq, t, side=probe, kind, player,
device=-1, tr=-1, value, text. Value — номер среза; у START это 0.
`t` берётся из часов текущего мира, `elapsedMs` — накопленное время наблюдателя.
Они не обязаны иметь одинаковое начало, часы двух процессов здесь не синхронизируются.

| kind | Содержание text |
|---|---|
| ENDPOINT_START | cycle, limit=30, isServer, isClient, rplMode; player=-1. |
| ENDPOINT_BINDING | cycle, revision, initial, pcChanged, entityChanged, idChanged, pc, controlled, previousPlayerId; player в оболочке — текущее значение. |
| ENDPOINT_SAMPLE | cycle, elapsedMs, bindingRevision, прежний PlayerState, members, rplMode. |
| ENDPOINT_DONE | cycle, samples=30, reason=LIMIT; означает окончание наблюдения, не доказанную готовность роли. |
| ENDPOINT_ABORTED | cycle, samples, reason=GAME_END/WORLD_CLEANUP/WORLD_CHANGED/GAME_START_RESET. |

Каждый успешный OnGameStart создаёт новый Probe и journal с seq=0; cycle растёт
в игровом объекте. Если мир в edit mode, Probe не создаётся. На каждом срезе
сначала пишется BINDING при первой/изменённой привязке, затем SAMPLE, затем
события существующего RadioReader. Отдельно сохранённые признаки наличия PC и
персонажа позволяют обнаружить исчезновение после обнуления слабой ссылки.
Revision — локальный счётчик наблюдений, не production epoch/lease.

RplMode — сырое числовое значение RplSession.Mode(), добавленное по ревью claude
#4574. Его смысл сверяется с установленным enum; одних isServer/isClient может
не хватать для различения одиночного режима и сетевого сервера.

Members — фактические числовые PlayerId из GetPlayers через `|`, NONE для
пустого списка, UNKNOWN при отсутствии PlayerManager. Имена профилей и ключи
раций не читаются для журнала. Несколько getter-ов не образуют атомарный снимок:
для приёмки пары нужны согласованные стабильные срезы и принадлежность ID peer
серверному списку. Неизвестный игрок в начале означает неготовность, а не
автоматически повреждённый журнал.

В конце каждого наблюдения — один Dump с прежними BEGIN/count/dropped/nextSeq и
END. Он должен точно повторять поток своего цикла. Повторный Stop не пишет
дубликаты; после LIMIT дальнейших срезов нет. Глобальная уникальность seq между
двумя Play одного процесса не требуется: это разные циклы.

## Приёмка до второго клиента

1. Source-review claude и независимый разборщик с отрицательными контролями.
2. Play Plain, mode=endpoint, без флага: ограниченное окно, ни одного события
   RICON_LIVE, нет новых ошибок загрузки по сравнению с известным baseline.
3. Тот же Play с флагом: ровно один цикл, 30 срезов, связные revision/личности,
   настоящий RadioReader, корректный Dump, отсутствуют мутации и VoN-подписки.
4. Play → Edit → Play в одном процессе: прекращение первого наблюдения,
   освобождение старых ссылок, свежий journal/revision второго цикла; никаких
   повторных тиков или дубликатов после Stop. Переключение делается штатным
   WorldEditor.SwitchToEditMode/SwitchToGameMode, мир не сохраняется.
5. После независимой приёмки этих пунктов — отдельный START первого Diag-peer.

До выполнения пунктов 2–4 код нельзя называть проверенным игровым bootstrap;
до пункта 5 не установлены клиентская роль, доставка данных или голос.

Для пункта 4 launcher принимает `-riconEndpointRestart=1` только с mode=endpoint
и включённым Probe. Отдельный Workbench-поток ждёт не менее трёх срезов через
read-only Game→Probe getter, запрашивает Edit, ждёт устойчивый edit-мир и запрашивает
второй Play. Первые два ожидания ограничены 600 проверками с Sleep(100); внешний runner
ограничивает весь процесс и ждёт два dump=END. Первый цикл должен завершиться
ABORTED после 3…29 срезов, второй — DONE. Если первый уже дошёл до LIMIT, опыт
не проверил раннюю очистку и не принимается как restart PASS.

Первый restart (23:58:51) подтвердил GAME_END после трёх срезов и полный dump из
8 событий, но второй Play не наступил: запрос отправился во время восстановления
редакторского мира. Прежнего IsGameMode=false было недостаточно. Исправленный
launcher ждёт один и тот же непустой мир с IsEditMode=true не менее пяти секунд
(51 проверка, 50 пауз), пишет EDIT_STABLE, один раз запрашивает Play и ещё до
30 секунд ждёт фактический IsGameMode=true. Успех — SECOND_PLAY_ENTERED, иначе
REFUSED без повторов. Это проверяемая попытка после стабилизации, а не универсальная
гарантия загрузки за пять секунд. Повторный runtime для этой правки ещё впереди.
