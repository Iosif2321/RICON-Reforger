## Подтверждённая структура

Предпочтительная база PE: `0x140000000`. VA ниже относятся к этой базе, не к адресам живого процесса.

| Объект проверки | Адрес / значение | Установлено |
|---|---|---|
| Одна функция по `.pdata` | `[0x1407CEE30, 0x1407CF23B)`, 1035 байт, 220 инструкций | Ограниченный разбор и декомпиляция исполнены |
| Строка `TransmissionQuality` | file offset `0x19C7B70`, RVA `0x19C8970`, VA `0x1419C8970` | Адрес строки передаётся вызову по имени |

| Vtables того же объекта | `0x1419C8868`, `0x1419C88A8`, `0x1419C88C8` | Общий RTTI TypeDescriptor `0x1420C9F10`, имя по `0x1420C9F20` — `gamecode::VonStream` |

Подтверждён поиск параметра по строковому имени с сохранением результата в `VonStream`.
В первом проходе роль 32-битного результата как индекса/ID/handle оставалась гипотезой; ниже она уточнена
отдельным разбором helper. Наличие в той же функции ссылок `VON_RADIO`/`VON_DIRECT`
согласуется с аудиопотоком, но не раскрывает формулу качества или алгоритм выбора получателей.

Продолжение по трём vtables ограничено инвентаризацией. Подходящий потребитель `VonStream+0x50` не выбран:
проверенные slots ведут к коротким type/size-подобным методам, adjustor-thunks и двум соседним телам.
Отсутствие отдельных искомых encodings в этих телах не доказывает отсутствие чтения поля в callees
или невиртуальных методах. Новый проход по случайно соседним функциям не запускался.

## Уточнение контракта helper

По продолжающемуся поручению owner #2960/#2970 и «продолжайте» выполнен один дополнительный разбор:
`[0x1409FC090, 0x1409FC115)`, **133 байта, 42 инструкции**, file offset `0x9FB490`.
SHA-256 этих байт: `2e1e5200e78e44bcb63e8a89554a5486b9077b6b7be8e07c9afd65fe2b568926`.
Входной EXE и его SHA те же; основной codex повторно проверил хэш после прохода.

Helper возвращает **порядковый индекс записи с нуля либо 32-битный `0xFFFFFFFF`**, не float качества.
Основной codex проверил ASM `stdout.log:418–459` и оба пути возврата:

- `0x1409FC0B4` обнуляет индекс; указатель таблицы — поле `+0x8`, количество — `+0x14`, шаг записи 32 байта.
- При совпадении указателей либо нулевом результате вложенного сравнения `0x1409FC111` возвращает индекс.
- Null/пустое имя, нулевое количество записей и отсутствие совпадения ведут к `0x1409FC0F7` и `0xFFFFFFFF`.

Вместе с первым caller это устанавливает: `VonStream+0x50` хранит индекс найденного `TransmissionQuality`.
Стабильность индекса при изменении таблицы не проверена. Точный контракт сравнения остаётся неизвестным:
тело callee `0x14081BB40` не анализировалось. ASM передаёт ему два аргумента в RCX/RDX; декомпилятор потерял
второй аргумент, поэтому его предполагаемый прототип не используется как доказательство.

Единственный дополнительный Ghidra-проход — 79.458 с, прежние noanalysis/readOnly/loadLibraries=false,
два CPU, heap 2 ГБ, decompile 30 с и общий предел 5 мин. Собственный PID 30544 завершён; временный проект удалён
режимом readOnly. Новых функций, соседних тел или vtables этот проход не затрагивал (agora #3097–3098).

## Точный следующий вопрос

Найти невиртуальный потребитель сохранённого поля `VonStream+0x50` для того же SHA, затем раздельно проследить
полученный lookup-result и числовое значение, которое попадает в audio setter. До выбора точных функций
широкого анализа не планируется.

Остаются **UNKNOWN**: формула native quality; её связь с расстоянием/рельефом/ключом; выбор получателей;
адресация на talker/listener; допустимый in-mod actuator. Существующий `BLOCKED_NO_ACTUATOR` не снят,
физическая модель RICON по результату RE не менялась.
