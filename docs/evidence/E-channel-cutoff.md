# P1 и P1b — проверка границ полезного канала

2026-10-22, codex. Уровень **HOST_ONLY / AGENT_REVIEW**, не игровое исполнение.
Источник истины — этот репозиторий; план владельца в Agora #3313/#3324/#3325,
реализация поручена #3327. Права на игру/мир/сервер этим поручением не расширялись.

## Что добавлено

- `REQ-channel-cutoff.md` и Python Assess: решение о численной отсечке всего полезного вклада.
  Строгие границы конечной мощности всех составляющих агрегируются по амплитуде; неизвестные
  фазы не позволяют применять обычную сумму мощностей. Неизвестность/ресурс не дают физический LOST.
- Проверки времени, версии среды и наличия всех границ; равенство допуску не отсекается.
  Среднее/перцентиль не подменяют строгую границу временного процесса. Отсутствующий численный запас
  запрещает отсечку. Неполный бюджет не выдаётся за полный, отсутствующий слой не становится нулём.
- `REQ-channel-time.md`: нормативная подготовка обязательного P1b. Физическая последовательность
  не перезапускается при PTT/TTL/resync; средний и мгновенный бюджет различаются. Временное описание
  требует миграции producer/clone/receiver/seam/фикстур и проверенной привязки ко времени сервера.
  Это пока требования, не реализованный дескриптор и не модель реальной речи.

## Границы результата

Enforce P1, генератор его фикстур и Workbench parity пока не выполнены. Производственные вызовы
к assessor не подключены: модель ещё должна выдать строгую границу с учётом наблюдений и времени,
а численный профиль — подтвердить запас для арифметики реализации. Коэффициентов по умолчанию нет.
Экономия вычислений/производительность не измерены. Реальные препятствия, краткие просветы речи,
server-authoritative доставка и звук этим срезом не подтверждены. P1b код начинается после P2.

Следующий шаг: завершить P0 Enforce и взаимную native-проверку; затем P1 Enforce по замороженному
корпусу, P2 наблюдения и проверяемая временная модель. Таблицы статуса ведёт claude после ревью.
