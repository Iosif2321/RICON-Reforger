# P1 и P1b — проверка границ полезного канала

2026-10-22, codex. Уровни **HOST_ONLY / AGENT_REVIEW**, затем **ENFORCE_PARITY** отдельного Assess;
не игровое исполнение и не подключение отсечки к основному расчёту.
Источник истины — этот репозиторий; план владельца в Agora #3313/#3324/#3325,
реализация поручена #3327. Права на игру/мир/сервер этим поручением не расширялись.

## Что добавлено

- `REQ-channel-cutoff.md` и Python Assess: решение о численной отсечке всего полезного вклада.
  Строгие границы конечной мощности всех составляющих агрегируются по амплитуде; неизвестные
  фазы не позволяют применять обычную сумму мощностей. Неизвестность/ресурс не дают физический LOST.
- Проверки времени, версии среды и наличия всех границ; равенство допуску не отсекается.
  Среднее/перцентиль не подменяют строгую границу временного процесса. Отсутствующий численный запас
  запрещает отсечку. Неполный бюджет не выдаётся за полный, отсутствующий слой не становится нулём.
- `REQ-channel-time.md`: нормативная подготовка обязательного P1b. Физическая последовательность
  не перезапускается при PTT/TTL/resync; средний и мгновенный бюджет различаются. Временное описание
  требует миграции producer/clone/receiver/seam/фикстур и проверенной привязки ко времени сервера.
  Это пока требования, не реализованный дескриптор и не модель реальной речи.

## Независимый прогон Enforce

Код/стенд claude `f8db35d`, документация `E-channel-cutoff-enforce.md`; согласование codex #3402.
Один скрытый пробник без мира на HEAD `8ac83dc`: PID 24384, exit 0, SHA четырёх проверяемых файлов
до/после совпали (`sourceStable=true`). Лог `ricon-cutoff-codex-20261022-224631/console.log`, SHA-256
`8776128fa0180b3669a2f43a8678000e4873d572dd2e785eb40a40868ca51339`.

Внешний валидатор `receipts/p1-log-check-codex.py` (15 отрицательных контролей самого валидатора)
сверил **24/24 решения, причины, zero, U**, immutable 24, controls 7, extras 3, host-only 3,
SCRIPT(E) 0, FAIL 0, один done: PASS и SHA корпуса. Отдельно сверена напечатанная граница 4096 путей.
Ошибки JSON-типа C23/C24/C26 не выдаются за native-проверку. Генератор `--check` 24+3, его 6 unit и
12 unit эталона codex повторил успешно. Полные старые Workbench-пробники снова не запускались:
существующие модули не менялись, согласовано #3395/#3397.

Квитанции: `receipts/p1-native-run-codex-20261022.json` (PID/exit/HEAD/исходные SHA) и
`receipts/p1-log-recheck-codex-own.json` (сверка напечатанных полей и фактические численные отклонения).
Наблюдаемый максимум ΔU около **0.000002 дБ**, это результат на этих векторах, не универсальная
граница ошибки native-арифметики. Допуск компаратора 0.001 дБ не используется для ветвления.

Первый запуск стенда claude аварийно завершился из-за форматирования 3.4e38 с девятью знаками.
Исправление касается тестового Capture/печати; история и SHA аварийного журнала сохранены в
`E-channel-cutoff-enforce.md`, отчёт не отправлялся. По замечанию codex #3388 исправлено различение
NaN/±Inf в проверке неизменности, отрицательный контроль исполнен в итоговом стенде.

## Границы результата

Производственные вызовы к проверенному assessor не подключены: модель ещё должна выдать строгую
границу с учётом наблюдений и времени,
а численный профиль — подтвердить запас для арифметики реализации. Коэффициентов по умолчанию нет.
Экономия вычислений/производительность не измерены. Реальные препятствия, краткие просветы речи,
server-authoritative доставка и звук этим срезом не подтверждены. P1b код начинается после P2.

P0 Enforce также принят обеими сторонами (итог codex #3380, receipts `8aaacdd`). Следующий шаг:
P2 наблюдения, их независимый эталон и Enforce; затем проверяемая временная модель. Требования P1b
v0.2 согласованы (#3386), конкретная временная модель ещё не реализована. Таблицы статуса ведёт claude.

## Уточнения владельца после приёмки P1

- **Agora #3412:** фактическое «нет связи сейчас» остаётся обязательным. Расчётный LOST и принятый Assess
  не доказывают полного прекращения голоса. Это не объявлено недостижимым: S4/actuator должен обеспечить
  отсутствие полезного голоса на соответствующей паре/интервале с последующим восстановлением просветов.
- **Agora #3415:** для текущего P2 **один класс WATER и один усреднённый профиль**, без определения
  пресной/морской воды или конкретного водоёма. Положение антенны относительно воды и участки пути
  сохраняются; солёность/температура не обязательные данные движка. Это имеет приоритет над прежним
  пунктом о распознавании типа воды. Числа среднего профиля задаются явно, допущения не становятся
  измеренными свойствами карты. ACK codex #3417, передано claude #3418.
- Сохранённый P.527-6 найден локально в прежнем scratchpad claude: DOCX SHA cbb067b9…db27f из E-web6,
  путь и SHA текста переданы #3407/#3408. Повторная загрузка для P2 не требуется.
- На момент записи P2 REQ/корпус ещё не переданы codex для независимого пересчёта; Enforce P2 не начат.
  Порядок остаётся: REQ+эталон claude → слепая проверка codex → freeze → Enforce codex → взаимная приёмка.
