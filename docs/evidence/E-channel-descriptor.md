# CT10.1 — авторский эталон переносимого дескриптора

2026-10-23, codex. **AGENT-REVIEWED / BLIND_CHECK_PASS**, native ещё ожидается.
Это подготовительный блок; snapshot v1, producer/receiver/seam и Game-код не менялись.

## Что проверено

`REQ-channel-descriptor.md` v0.1 задаёт RCFD/1: самодостаточное описание существующего CF0.2, точные int32/binary32,
ограничение размера без обрезания составляющих и Rebase только якоря того же процесса. Нулевой вес канонизируется
к +0; минимальный положительный вес 2^-149 сохраняется. Полнота/ресурс и OUT_OF_MODEL_DOMAIN не превращаются в LOST.

Авторский корпус `oracle/vectors/channel_descriptor_v1.json`: **54** случая, LF SHA-256
`95208dd198cee4680763e6813cb66374832ef241ea1b5590e20799d834f2aa27`.
Корпус построен из авторского эталона; его 54/54 — не независимая проверка.
Host-only: D17, D18, D19, D20, D21, D31, D47, D54 (ошибки структуры/типов JSON); остальные 46 выразимы типизированным API.

Claude независимо реализовал CD02–CD07 только по REQ и JSON, не читая авторский oracle/build/test:
`docs/evidence/receipts/ct10-1-independent-req-check.py`, commit `f1d338e`, Agora #3632.
Результат: 54/54, 48/48 контролей изменения байтов, 54 проверки непрерывности Rebase,
размеры 5111/5066. Выбор big-endian согласован. Codex повторил этот checker; после добавления
ручного `goldenHex` и статуса в metadata сравнил все 54 входа/ожидания и hostOnly с `af93d50`:
они не изменились. Повтор checker с новым SHA также PASS; файл checker партнёра не менялся.
Композиционность Rebase явно записана в CD06 и уже покрыта авторским тестом.

11 unit-тестов проверяют:

- вручную размеченную golden-последовательность CD07 длины 102 байта;
- точные 5066 байт максимального поддерживаемого описания и отказ при бюджете 5065;
- структурный максимум 5111 байт для ключа другой модели;
- +0/-0 и минимальный положительный subnormal, FLT_MAX, полный int32 доплера;
- отсутствие алиасов и неизменность исходных объектов/байтов;
- приоритет бюджета до обхода элементов и строгий разбор заголовка/хвоста;
- одинаковые phasesQ/real/imag/gainDb до и после Rebase, включая subUs=999, составной перенос и время около int.MAX;
- 128 дополнительных воспроизводимых round trip/Rebase с различными фазами/доплерами;
- все 9 кодов отказа/успеха и соответствие корпуса сборщику.

## Воспроизведение

```powershell
python -X utf8 -B oracle/build_channel_descriptor_vectors.py --check
python -X utf8 -B oracle/channel_descriptor_oracle.py --check oracle/vectors/channel_descriptor_v1.json
python -X utf8 -B -m unittest discover -s oracle -p test_channel_descriptor_oracle.py
```

Использованы stdlib struct/json и уже принятый CF preflight/phase_at. Существующие CF и snapshot-корпусы не менялись.
Общий host-runner пока не меняется до согласования этого нового контракта; точечные проверки пройдены.

## Граница доказательств

Размер относится только к RCFD/1, не включает Rpl/RPC/сетевые заголовки. Официальный ScriptBitWriter/Reader
подтверждает наличие операций чтения/записи, но байтовая совместимость с внутренним потоком движка этим не измерена.
Нативный адаптер должен доказать точный round trip, включая subnormal; half/Float01 не заменяют binary32.
Фактическая доставка, происхождение реального отправителя, адресность клиентам, CT06-clock mapping, производительность,
целостная миграция schema 2, изменение физических параметров и голос остаются открытыми. Полный CT10 не закрыт.
