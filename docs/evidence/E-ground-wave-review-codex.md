# Земная волна — независимая проверка контракта и корпуса

2026-10-24, codex. **INDEPENDENT_REFERENCE_PASS** для REQ-ground-wave v0.1, корпус 265 случаев.
Первоначальные 263 случая проверены слепо: авторский Python-эталон, генератор и unit-тесты до завершения этой
проверки не читались и не импортировались. Затем ревью реализации обнаружило ещё два случая JSON; весь
обновлённый корпус повторно проверен тем же независимым скриптом и собственной C++-сборкой.
Это проверка контракта и паритета к исходной реализации NTIA, не новая независимая физическая модель.

## Исправления, вызванные ревью

1. **Смысл основных потерь** (#4056). Lb определён для изотропных антенн; 4.77 dBi нормирует опорное поле,
   а не является двумя уже учтёнными усилениями в Lb. Подстановка нормированного поля 1 в GW04 даёт FSPL
   с расхождением около 1.4e-14 дБ. Определения: [P.341-7 §1.2 и §2.1](https://www.itu.int/dms_pubrec/itu-r/rec/p/R-REC-P.341-7-201908-I!!PDF-E.pdf),
   [P.368-10 Annex 1 NOTE 1](https://www.itu.int/dms_pubrec/itu-r/rec/p/R-REC-P.368-10-202208-I!!PDF-E.pdf).
2. **Знак усилений** (#4074). Уточнён бюджет Pr = Pt + Gt + Gr − Lb; потери между реальными антеннами
   Lt = Lb − Gt − Gr. Автоматические поправки ±6.02/±9.54 дБ запрещены; реальные антенны у земли — отдельный REQ.
3. **Покрытие численного отказа** (#4088). В первоначальных 257 случаях не было NUMERIC_FAILURE.
   Собственная сборка показала не конечный результат при конечных ε′/σ до 1e308. Добавлены два таких случая,
   два случая исключения и два успешных при большой проводимости; проверена новая граница отказа GW246–GW249.
4. **Целые JSON вне binary64** (#4119, после слепой проверки). `float(10**400)` выбрасывал OverflowError до
   обработчика численного этапа. Общий преобразователь исправлен, два JSON-only случая дают INVALID_INPUT;
   обновлённый корпус 265/265, авторский CLI и 18 unit-тестов самостоятельно запущены Codex и пройдены.

Первая сборка собственной оболочки с `/EHsc` завершалась аварийно на исключении, проходящем через `extern C` API.
Проверено по [документации MSVC](https://learn.microsoft.com/en-us/cpp/build/reference/eh-exception-handling-model):
эта опция разрешает предполагать, что C-функции не бросают C++-исключений. После замены на `/EHs` обычные
C++-исключения корректно обрабатываются по строке. Сами численные исходники NTIA не изменены; аварии памяти
не перехватываются и успешным результатом не считаются.

## Воспроизведение и пределы

Сборка: вызвать штатный `vcvars64.bat`, затем из собственной временной папки собрать нашу оболочку и
`LFMF-main/src/*.cpp` с `/EHs /O2 /std:c++17`, include `LFMF-main/include`, определениями
`LIBRARY_NAME=\"LFMF\"`, `LIBRARY_VERSION=\"1.1\"`. Не использовать исходники Python-порта вместо NTIA.

```powershell
python -B -X utf8 docs/evidence/receipts/ground-wave-blind-check-codex.py --exe '<temp>/ntia_reference_codex.exe' --source-zip '<temp>/lfmf-source.zip' --source-dir '<temp>/source/LFMF-main' --test-data-zip '<temp>/lfmf-test-data.zip' --report '<temp>/ground-wave-check.json'
```

Перед новой сборкой проверяющий скрипт требует те же архивы и REQ. Версия exe может получить другой SHA
после перекомпиляции; в отчёте фиксируется реально использованный файл. Это host binary64, не Enforce binary32.
Не закрыты реальные грунты, ионосфера, рельеф/смешанные трассы, антенны, подключение к оценщику и звук в игре.
Диагностики kr и h/λ сохраняются; сами по себе они не дают универсального вердикта применимости метода.
