## Что реализовано

- `RICON_PathObservation.c`: типы пяти семейств, проверка покрытия/геометрии/порядка/материальных знаний,
  нормативная длина binary32 и объединение пересекающихся/касающихся водных интервалов.
- `RICON_WaterLayer.c`: ITU-R P.527-6 (8)–(27), частотное затухание воды и оценка потерь на внешних границах.
  Входы и выходы разделены; результат не содержит ссылок на входные сегменты.
- Слой считает только заданный прямой путь. Глубина антенны — наблюдение; она не прибавляет повторные потери
  и не заменяет путь вертикальным выходом к поверхности. Для полностью подводного [0,L] воздушных границ нет.
- Неполное покрытие и неизвестная среда не превращаются в LOST. Непредставимая ε или результат дают
  NUMERIC_FAILURE. Общий профиль имеет только температуру и солёность, производственного конфига по умолчанию нет.

Существующие LinkEvaluator, P1, S3/S3b, snapshot v1 и голосовые адаптеры не вызывают эти классы и не изменены.
Потери нормального падения — модельная оценка: строгой границы для P1 здесь нет.
Преломлённый маршрут требует отдельной геометрической кандидатуры с новыми наблюдениями воздушной части.

## Воспроизведение

```powershell
python docs/evidence/receipts/p2-independent-req-check-codex.py oracle/vectors/path_observation_v1.json
python tools/RICON_TestRunner/gen_path_observation_fixture.py --check
python -m unittest discover -s tools/RICON_TestRunner -p test_gen_path_observation_fixture.py
python docs/evidence/receipts/p2-log-check-codex.py --receipt docs/evidence/receipts/p2-native-run-codex-20261022.json
```

Это не игровая приёмка, не измерение FPS и не подтверждение полного подавления голоса. Сбор наблюдений из мира,
калибровка водного профиля, временные просветы P1b, остальные препятствия P3–P5 и аудио S4 требуют своих срезов.
