# P3.3 — доступные данные геометрии пути

2026-10-23, codex. **DOC_ONLY / на взаимное ревью**. Первичный API прочитан онлайн; трассы в мире не
исполнялись. Это уточнение PO08 и MS09 для следующего среза, не готовый адаптер объектов.

## Что даёт API

| Данные | Подтверждённое значение | Следствие для P3.3 |
|---|---|---|
| `BaseWorld.TraceMove` | Возвращает долю пройденного пути 0…1, результат помещает в `TraceParam` | Для точечной трассы положение на пути вычисляется из начала, конца и доли; толщину ещё нужно установить |
| `BaseWorld.TracePosition` | Проверяет пересечение в начальной позиции, отрицательное значение описано как глубина проникновения | Это отдельный запрос, его результат нельзя считать выходом луча из стены |
| `TraceFilterCallback` | Колбэк для фильтрации сущностей на пути | Сам по себе не является перечнем пар вход/выход материала |
| `TraceParam.TraceNorm`, `TraceEnt`, `ColliderIndex`, `NodeIndex` | Нормаль полигона, сущность и идентификаторы коллайдера/кости | Можно сохранять свидетеля контакта; повторная стабильность индексов не подтверждена |
| `TraceParam.TraceDist` | Расстояние плоскости полигона | Не толщина стены и не пройденная длина луча |
| `SurfaceProps`, `TraceMaterial` | Свойства поверхности; текстовый материал обычно доступен лишь для рельефа | Нет гарантии заполненного имени материала у каждого модового объекта |
| `ANY_CONTACT`, `ALL_CONTACTS` | Первый режим останавливается при контакте; второй описан как выдача всех контактов через колбэк | Порядок, повторные грани и состояние `TraceParam` внутри колбэка требуют проверки на установленной сборке |

Источники: [BaseWorld: TraceMove/TracePosition](https://community.bistudio.com/wikidata/external-data/arma-reforger/EnfusionScriptAPIPublic/interfaceBaseWorld.html),
[поля TraceParam](https://community.bistudio.com/wikidata/external-data/arma-reforger/EnfusionScriptAPIPublic/interfaceTraceParam.html),
[TraceFlags и сигнатура TraceFilterCallback](https://community.bistudio.com/wikidata/external-data/arma-reforger/EnfusionScriptAPIPublic/group__World.html).
Документация `ALL_CONTACTS` и описание фильтра недостаточны, чтобы заранее утверждать получение всех пересечений
граней одного сложного коллайдера. Это открытый вопрос опыта, а не доказанная недоступность.

## Связь с существующим кодом

`REQ-path-observation.md` PO04 уже хранит интервалы объектов и признак проёмов. `REQ-object-rf-profile.md`
разрешает профиль по метаданным или проверенному правилу, но не устанавливает геометрию. `REQ-material-slab.md`
MS03/MS09 требует толщину по нормали, угол, поляризацию и электрические параметры; P3.2b выдаёт последние для
одной частоты. Повторный реестр объектов или вычислитель материала не нужен.

Вывод для реализации: попадание в габарит дома не доказывает сплошной материал между крайними фасадами.
Обратная трасса также не доказывает, что её первый контакт — выход из той же стены: между фасадами могут быть
воздух, несколько стен и проёмы. Это геометрическое ограничение предложенного способа, а не новое свойство API.
Неполные данные должны сохранять неизвестность по PO04; ими нельзя обосновывать нулевые потери или ранний LOST.

## Следующий проверяемый срез

Один TOOL_ONLY опыт с точечными трассами на контролируемой геометрии, с сохранением входов, доли, нормали, сущности, индексов,
поверхности, флагов и порядка колбэков. Сначала сравнить одну трассу и `ALL_CONTACTS`, затем обратное направление.
Геометрия и маска столкновений фиксируются в журнале, существующая матрица взаимодействий не меняется.

1. Одна замкнутая прямоугольная стенка известной толщины: нормальный и наклонный луч, начало снаружи и внутри.
2. Две раздельные стенки с воздухом между ними: пустой промежуток не становится материалом.
3. Проём: луч через пустое отверстие и рядом через стенку, открытая/закрытая дверь как разные состояния.
4. Составной коллайдер и объект с отсутствующими RF-метаданными: отсутствие данных остаётся явным.

После опыта — контракт нормализации контактов в интервалы PO04 и входы MS03, независимый корпус и только затем
адаптер мира. Прохождение луча через отверстие не доказывает отсутствие радиоволновой дифракции у его краёв;
эта физическая модель выбирается отдельно. На текущем шаге ни P3.3, ни работа на реальной карте не закрыты.
