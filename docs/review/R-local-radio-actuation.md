## 1. Нормативные границы

[INTENT LS-01…08](<../req/INTENT-local-radio-slice.md#L23-L64>) требует штатный A→B путь, отдельно `DESIRED`, `APPLIED`, `OBSERVED`, восстановление и сохранность direct. [REQ-von-seam](<../req/REQ-von-seam.md#L10-L25>) для валидного snapshot всё ещё возвращает `BLOCKED_NO_ACTUATOR` и не даёт разрешения менять engine. [S2](<../req/REQ-radio-device-adapter.md#L21-L50>) принимает серверные observation/profile, не доказывает их runtime provenance, а native frequency кГц подтверждён только у определённых точек AN/PRC-68. [S3](<../req/REQ-pair-service.md#L91-L116>) различает `EVALUATED` и валидность budget. [S3b](<../req/REQ-link-publication.md#L12-L17>) отдаёт snapshots вызывающему коду, не выполняя сетевую доставку. Поэтому snapshot LOST сам по себе не эквивалентен MODEL_LOST и тем более слышимому запрету.

Исторический oracle/Workbench PASS проверяет вычисление и статическую совместимость, но не калибрует RF-разборчивость, физическую слышимость, native mute-stage, runtime authority или право на мутирование. `TEST_ONLY` параметры и синтетический LOST нельзя подменять реальным физическим отказом.

## 2. Предварительная матрица контролей (всё NOT_RUN)

У каждого опыта: зафиксировать два реальных персонажа и единственную направленную пару A→B, полные server-resolved epoch/generation/player/device/transceiver/lease и terminal handles; source revision, SHA, порядок попыток, конфиг, физические входы, scope актуатора и отрицательные наблюдения. B фиксирует самостоятельно наблюдённое и распознанное содержимое до раскрытия тестового A-маркера; A не доставляет expected bits B через RPC, общий файл, память, конфиг или известный seed. Путь наблюдателя B обязан иметь отдельную квалификацию *после* фактического radio gate. Если наблюдение прервалось, это `INCONCLUSIVE`, не отрицательная доставка.

| Контроль | Предусловие/действие будущего опыта | Допустимый вывод; иначе |
|---|---|---|
| Positive A→B, gate открыт | Реальный native TX A и live RX B; действующий binding, реальный валидный budget и незаблокированный actuator; свежий не известный B шаблон. | Только независимый распознанный B-output того же native тракта + source/identity evidence дают LS-02/03 для заявленного носителя. TX/PTT, callback, один CRC или местный звук без B-output — `INCONCLUSIVE`. |
| Radio-only restriction и recovery | На **той же геометрии и binding** серверный MODEL_LOST из измеренных входов либо иной явно названный RICON decision; до активации I2 нативный A→B канал при этом *должен реально доставлять* свежий сигнал. Затем отдельно `DESIRED`→`APPLIED`/readback→B-output; восстановление только own delta с повторным положительным B-output. | LS-05 можно обсуждать только при причинно связанном реальном изменении доставки и её восстановлении в заявленном scope. Если сама геометрия уже блокирует native, отсутствие B ничего не говорит об актуаторе; выбирать после результата другую модель/порог нельзя. Ручной mute, synthetic snapshot, data-plane флаг у декодера, pre-mute RX callback или исчезновение из-за перемещения B — `BLOCKED/INCONCLUSIVE`. |
| No-TX | Не начинать реальную передачу A; B наблюдает полный тайм-аут с живым RX/выходом и записывает все попытки. | Отсутствие нового распознанного B-маркера — отрицательный контроль; отсутствие наблюдателя — `INCONCLUSIVE`. |
| Path open / no B | Реально разомкнутый native путь либо физически отсутствующий B, не просто локальный флаг. Оставшийся B-канал наблюдения должен иметь валидный контроль работы, если B присутствует. | Ложный распознанный маркер — `FAIL`; отсутствие доказанного разрыва/присутствия B или живого канала — `INCONCLUSIVE`. |
| Local fake TX | Вызвать лишь локальный индикатор/имитацию без реального native отправления; приёмный callback вручную не вызывать. | B не распознаёт новый маркер; любой marker при таком контроле доказывает обходной канал/ложную положительную атрибуцию (`FAIL`). |
| Direct before/during/after | При неизменной геометрии во время действия radio restriction отдельно провести последовательные DIRECT A→B пробы с другим содержимым; до и после — положительные direct-контроли. Не передавать radio/direct одновременно. | Только независимый положительный direct B-output во всех трёх состояниях поддерживает LS-06 в указанной области. У radio-only observer null receiver отбрасывается: отсутствие direct callback не является PASS. Нет изолированного выхода B или подтверждённого direct TX — `INCONCLUSIVE`. |
| Stale/rebind/abort | Устаревший epoch/lease, смена generation, device/transceiver/owner, observer gap и неудачный readback. | Старое решение не действует на новый binding; только собственный однозначно захваченный state возвращается. Любая запись при неясном ownership или безусловный unmute — критический `FAIL`; неизвестность — fail closed/`INCONCLUSIVE`, не положительный LS-05. |

Для звуковой ветви нужно отдельно квалифицировать физический источник A и **изолированный B-output**: общий Windows USB mix не является выходом B. Для пакетной ветви микрофон/микшер не являются обязательными лишь после доказательства идентичного штатного пути и протокола, native-delivery участка и radio gate; AI-event и RX timing не получают эту эквивалентность автоматически. Не использовать whole-player Social mute или пользовательские/платформенные direct настройки.
