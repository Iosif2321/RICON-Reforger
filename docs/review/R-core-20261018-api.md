# Ревью ядра RICON: Enforce API, синтаксис и подключение

Дата: 2026-10-18. Автор проверки: codex. Проверяемая ревизия: `ecf95ac`.

Статус: **STATIC REVIEW / DOC_EVIDENCE**. Это не `WORKBENCH_COMPILE_PASS` и не runtime-доказательство.

## Мини-intent

- **Проблема:** черновик `addons/RICON_Core` не компилировался, а перечисление API в ADR-002 не проверяет
  владение объектами, editor-safe доступ и фактическое подключение компонента.
- **Результат:** подтверждённые сигнатуры, compile/integration gaps и минимальный список правок до oracle.
- **Затронуто:** пять `.c`, `addon.gproj`, ADR-002 и будущий compile gate.
- **Ограничения:** без Workbench, Play, сервера и reverse engineering; только репозиторий и офлайн Script API.
- **Открыто:** GUID зависимости проекта, реальная компиляция и загрузка компонента проверяются заказом
  `[Workbench]` №001, пункт 10.

## Findings

### API-01 — HIGH / FIX: `RICON_LinkEvaluator` хранит модель слабой ссылкой

**Код:** `Propagation/RICON_LinkEvaluator.c:15-20`.

`m_Model` объявлен без `ref`. Официальная документация ARC говорит, что поля-ссылки Enforce по умолчанию
слабые; `ref` делает их сильными (`Page_Enforce_EnforceScriptARC.html:159-188`). Локальные переменные сильные
только на время вызова (`:178-188`), а рекомендуемый владелец должен держать одну сильную ссылку (`:195-197`).

Следствие: контракт конструктора допускает `new RICON_LinkEvaluator(new RICON_FreeSpaceModel())`, но после
возврата из конструктора временная сильная ссылка может исчезнуть, `m_Model` станет `null`, и `Evaluate()`
вернёт невалидный бюджет. Сейчас map менеджера держит зарегистрированные модели сильными
(`RICON_CommsManagerComponent.c:13`), однако такой внешний lifetime нигде не является предусловием evaluator.

**Минимальная правка:** выбрать и записать владение. Для самостоятельного evaluator —
`protected ref RICON_PropagationModel m_Model`; если ссылка намеренно borrowed — зафиксировать обязательный
registry-owner и запретить transient model contract-тестом. До решения oracle не должен закреплять этот lifetime.

**Проверка:** contract/self-check создаёт evaluator с единственной новой моделью, затем вычисляет один FSPL-вектор;
после этого `WORKBENCH_COMPILE_PASS`.

### API-02 — MEDIUM / FIX: `GetInstance()` разыменовывает потенциально отсутствующий `GetGame()`

**Код:** `Core/RICON_CommsManagerComponent.c:17-23`.

Метод проверяет `gameMode`, но сначала без проверки вызывает `GetGame().GetGameMode()`. Офлайн API подтверждает
`ChimeraGame.GetGameMode()` (`interfaceChimeraGame.html:139,388-394`), а документация Reforger прямо допускает
`GetGame() == null` в edit mode (`interfaceSCR__Global.html:2060`). Публичный static helper поэтому не editor-safe.

**Минимальная правка:** сначала сохранить и проверить `ChimeraGame game = GetGame()`, затем получать GameMode.

**Проверка:** compile + статический self-check вызова при отсутствии game; runtime-поведение не заявлять.

### API-03 — MEDIUM / FIX: server gate размазан и использует API с предупреждением о немодульности

**Код:** `Core/RICON_CommsManagerComponent.c:29,38,45,52`.

`Replication.IsServer()` существует (`interfaceReplication.html:133,404-425`), но официальный API предупреждает:
hardcoded `IsServer` не модульный и рекомендует replication roles/ownership (`:425`). При этом
`OnPlayerConnected(int)` уже документирован как server-only
(`interfaceSCR__BaseGameModeComponent.html:594-610`); повторная проверка там избыточна. Для
`OnWorldPostProcess`, `OnPlayerDisconnected` и публичного `RegisterModel` authority contract надо определить
явно, а не молча игнорировать вызов клиента.

**Минимальная правка:** оставить один authority boundary у менеджера; после Workbench-сверки выбрать документированный
role/owner check. Server-only callback не дублировать. Невалидный вызов регистрации должен давать диагностируемый
отказ в dev-сборке, а не только `return`.

**Проверка:** compile; позднее adversarial client-call test в Э3. До runtime — `OPEN_BEHAVIOR`.

### API-04 — HIGH / GAP: компонент и контракты не подключены ни к одному ресурсу

**Код:** `Core/RICON_CommsManagerComponent.c:4-65`; весь `addons/RICON_Core`.

Пара `RICON_CommsManagerComponentClass : SCR_BaseGameModeComponentClass` /
`RICON_CommsManagerComponent : SCR_BaseGameModeComponent` соответствует доступным типам API, но в репозитории нет
prefab/config, который добавляет компонент к GameMode. Нет и caller для evaluator/routing/VoN seam. Поэтому даже
успешная компиляция пяти файлов докажет только доступность сигнатур, не выполнение `OnWorldPostProcess()`.

**Минимальная правка:** после исправлений ревью и compile gate добавить один минимальный test/prefab attachment либо
документированный способ внедрения в GameMode. Не создавать production-world до ответа Workbench.

**Проверка:** сначала `WORKBENCH_COMPILE_PASS`; затем SOURCE-подтверждение attachment. Runtime остаётся
`BLOCKED_NO_RUNTIME`.

### API-05 — BLOCKED_WORKBENCH: `addon.gproj` и цельная компиляция статикой не подтверждаются

**Код:** `addon.gproj:1-14`.

Синтаксис файла и GUID зависимости нельзя подтвердить Doxygen API. Прямое чтение vanilla game files запрещено;
проверка уже включена в `docs/evidence/WB-order-001.md:32-34`. Отсутствие ошибки в Markdown/Enforce-коде не равно
компиляции.

**Действие:** не менять GUID на догадке. Записать точный Workbench log, способ запуска compile и версию Tools в
`E-workbench-source.md`/`E-workbench-build.md`.

## Минимальный список правок оси C

1. **До oracle:** решить ownership `RICON_LinkEvaluator.m_Model` (API-01) и добавить lifetime self-check.
2. Добавить null-guard в `GetInstance()` (API-02).
3. Централизовать и документировать authority gate; учесть предупреждение `Replication.IsServer` (API-03).
4. Выполнить Workbench compile без Play, не угадывая GUID/сигнатуры (API-05).
5. Только после compile определить минимальный GameMode attachment для component (API-04).

## Итог

Вердикт оси C: **PARTIAL**. Все непосредственно вызванные Math/vector/container/lifecycle методы найдены в текущей
офлайн-документации, явного отсутствующего API не обнаружено. Но один дефект владения (`m_Model`), один null-safety
дефект и отсутствие resource wiring не позволяют считать ядро рабочим; цельная компиляция остаётся
`BLOCKED_WORKBENCH`.
