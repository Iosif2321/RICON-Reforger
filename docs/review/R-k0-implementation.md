### N1-R01 — backdated/replayed receive и порядок edges не определены

[N1:50](<../plan/PLAN-k0-neutral-model.md#L50>) требует marks≤NowMs и монотонный NowMs; [переходы:76–77](<../plan/PLAN-k0-neutral-model.md#L76-L77>) и [interval guard:107](<../plan/PLAN-k0-neutral-model.md#L107>) не задают порядок ReceiveMs между FRAME одной роли или относительно принятого DOWN_MARK/DOWN. В DTO нет seq; порядок вызовов Update сам по себе не доказывает порядок timestamp фактов. Это допускает неединственную реализацию CLOCK/phase guard и ложный MODEL_TRACE_CONSISTENT.

Контрпример (все прочие identity/generation/size facts валидны, OtherErrorMs=0): READY at0 → ARM at3000 → DOWN_MARK at3001 → DOWN A Receive3100/Now3101, callback interval [3050,3060,3070] → UP A Receive2000/Now3200, interval [1900,1950,1960]. Для DOWN N40/E10, для UP N50/E50; оба interval/type/range условия выполнены. HeldDue4600, checkUP3200<4600, PostUpDue5000. Написанные локальные guards разрешают POST_UP, хотя UP receive и весь callback interval строго раньше принятого DOWN. Такой trace не является упорядоченной парой DOWN→UP и должен быть invalid, а не legal-cycle success.

Минимальный corrective handoff автору через Lead: определить сохранённые per-role receive/edge order marks и fail-closed правила backdated/replayed FRAME, включая порядок DOWN_MARK→qualified DOWN→UP и отдельно допустимость equality/overlap при integer-ms resolution. Не выдавать synthetic physical provenance: marks только fake facts. Negative fixture выше должна начинаться с New и переходить по реальной истории; ожидается точная clock/order/phase ошибка, sticky invalid, no POST_UP/disarm/positive, неизменные active due и no retry. Можно явно включить новый subcase в существующий frozen vector с conjunction либо пересмотреть конечный count ДО writing; не дописывать произвольные tests после PASS. Manifest/caps/N/H/D/E/R менять не требуется. После frozen corrective SHA — только адресный re-review порядка/векторов, не повтор всей работы.
