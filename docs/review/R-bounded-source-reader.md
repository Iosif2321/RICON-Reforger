### Не маскировать failures частичным успехом

- `Read(...,1)` count=1/0/negative/>1 классифицируются отдельно. До expected EOF count0 — incomplete; для Enfusion нельзя просто унаследовать .NET EOF semantics. Close возвращает void: вызов без observable не превращать в доказанный native close/flush. Null/исключение/незавершённый close не clean PASS.
- Запись выбранного окна не снимает ошибки позже в scan. Если acceptance требует EOF/полную проверку ресурса, удерживать только bounded output до такого решения либо явно помечать ранний output как unqualified diagnostic; не печатать success до валидации. Весь файл может потоково сканироваться в пределах budgets без whole-file array — это не то же самое, что запретить любое чтение всех bytes.
- Strict ASCII означает rejection UTF-8 BOM, Unicode comments и иных non-ASCII; это допустимая заявленная узость, не поддержка UTF-8 source. Указать cases CRLF на boundary, bare CR на EOF, NUL вне output-window, TAB, line4095/4096/4097, output16383/16384/16385 с prefixes, missing anchor, insufficient lines, empty/trailing LF. Базовые six bytes `41 0A 42 0D 0A 43` не закрывают весь byte-representation domain; add fixed 0x80/0xFF negatives и poisoned previous scalar в будущий reviewed vector set, не создавать fixtures сейчас.
- Native-neutral не может впервые доказывать собственные обязательные process/log preconditions запуском. Native allocation semantics, mount identity и caller provenance остаются разными вопросами: даже корректное окно script override не показывает native caller или всех native writers для I2.

## 3. Положительный managed-handle кандидат — не принципиальная невозможность

В M2 public `Start()` при `UseShellExecute=false` выбирает `StartWithCreateProcess`. В выбранной ветви `processInfo.hProcess` после CreateProcess сохраняется через `procSH.InitialSetHandle`, затем `SetProcessHandle(procSH)` до успешного возврата. `GetProcessHandle` при `haveProcessHandle=true` возвращает сохранённый handle; PID-based `OpenProcess` стоит в другой ветви. Следовательно, отдельное позднее чтение свойства Handle **не обязательно** означает позднее приобретение handle: реальный путь важнее имени свойства. Этим уточняется blanket inference из отсутствия разрешённого interop, но не снимается residual proof obligation R1.

Для квалификации требуются source/build соответствие установленному Framework, единственный returned Process owner, `UseShellExecute=false`, fixed absolute executable/args/working directory, без credentials/elevation/shell/redirected pipes, отсутствие Close/Dispose/reattach до последнего необходимого wait/receipt. В reference source managed allocations/stream setup после native creation также требуют анализа исключений; отсутствие redirects сокращает, но не доказывает устранение всех failure gaps. Если Start не вернул own object, существование/cleanup процесса не выдумывать. Никаких GetProcessById/Stop-Process/name scan, P/Invoke/Add-Type или fallback после policy denial.

Эта находка достаточна для отдельного **doc/source qualification** задания, не для утверждения target runtime parity, гарантированной выдачи команды, no-children или disk cap. Native wrappers внутри штатной .NET библиотеки не равны добавлению пользовательского interop; разрешённость конкретного будущего launch всё равно проверяется отдельно.

## 4. Что записать нормативно до writing

Не нужна повторная валидация общей цели. Нужна отдельная reader-spec либо явно утверждённое normative extension в принятом source-of-truth, с requirement IDs и следующими проверяемыми границами:

1. **Назначение/исключения:** exact-known window source evidence, не доказательство authority/native writer completeness; neutral/model/source — разные capabilities, никакого hidden index или media/data plane.
2. **Модель данных и памяти:** byte event/count/EOF/error schema; limit units и equality; peak tool-owned refs/scalars/buffers/output; native allocation claims отдельно, никаких whole-file arrays, JSON-before-size-check или unbounded exception dumps.
3. **Parser acceptance:** byte decoding assumptions; ASCII/TAB/NUL/CRLF/bare-CR/EOF правила; line numbering, empty/trailing line, anchor/window completeness; pre-allocation output length включая wrappers; sticky failure и bounded terminal schema.
4. **Identity/IO:** exact allowlist/resource ID для fixture и source по отдельности, build/mount resolution, snapshot/change proof, short/error/Close semantics. Unknown не даёт qualified PASS.
5. **Host/process/storage:** для pure выбран реальный безэффектный host; native executor/runtime/ownership/child scope, все write roots/численные quota, no overwrite/delete/pruning чужих evidence, timeout/failed-exit receipts, policy STOP без обхода.
6. **Gates и evidence:** самостоятельные spec approval/record, bounded plan, fresh transition/явный waiver, write/source-review/pure/compile/native-neutral/source permissions. Command с BLOCKED/несуществующим runner не acceptance executable. Соответствие модели будущему Enforce adapter квалифицируется отдельно.

Этот список — finding для автора и Lead, **не записанная reviewer-ом spec**, не изменение существующих caps и не CODE GO. Точное число/путь новых нормативных артефактов выбирает Lead без создания дублирующих roadmap/spec.
