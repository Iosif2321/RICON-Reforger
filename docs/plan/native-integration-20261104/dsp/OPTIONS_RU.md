## Что уже можно повторно использовать

Обычная player voice сохраняет native capture, Opus, UDP/receive, decoder и Stream. На принимающем VoNComponent фабрика `14029FA70` ищет/создаёт VonStream по sender ID. Это отдельное состояние отправителя на данном слушателе, **не отдельный DSP instance каждого transceiver или логического RICON-устройства**. Другая клиентская машина имеет своё принимающее состояние. Текущая доставка нескольких устройств одному listener может перезаписать q/frequency одного routing record; downstream DSP не возвращает утраченное различие устройств.

У VonStream есть приватный ресурсный объект в поле+20 и cached index `TransmissionQuality` в+50. `1407CFAC0` читает первый float receive context и через `A1B690 → E9DFB0 → 9FAB40` передаёт его в параметры именно этого ресурса. Setter не вычисляет q и не ищет произвольный entity signal с таким именем. Последующее чтение source `SignalsManagerComponent` явно копирует четыре именованных параметра: `Interior`, `RoomSize`, `UnderPlayerControl`, `IsInPlayerVehicle`; это не доказательство универсального копировщика всех пользовательских сигналов. Качество записывается до проверки доступности source entity, поэтому отсутствие actor не отменяет эту запись, а обновление spatial/environment может пропускаться и сохранять прежнее состояние. См. [native audio report](<C:/Users/Ded/Documents/Projects/ARMA 3 Scripts/Cellular System/output/von-re-20261104/audio/REPORT.md:108>) и [lifecycle](<C:/Users/Ded/Documents/Projects/ARMA 3 Scripts/Cellular System/output/von-re-20261104/lifecycle/receive_environment.md>).

Текущие установленные `von.acp` SHA256 `a16accc24ccf90c0b5e9a2a46746b5a0716fb253603b20bdd1c917ff41ba8e20` и `Von.sig` SHA256 `3da1d2686164604562c7ea25ad381d8d77719798140f342a5e5cf8970260f39e` дают готовую radio обработку:

```
native decoded voice → Stream → общий direct-processing bus ─┬→ Direct shader
                                                           └→ radio input sum
local Brownian generator → Noise_V × base volume 0.2 ───────────→ radio input sum
radio input sum → Bitcrusher / Quality_W wet → HP → HardClipper → LP
                → Radio_V × base bus scale / gain ramp → Radio shader
```

Для конечного q в выбранном ресурсе `u=clamp(q,0,1)`; `Quality_W=.85-.65u`, `Radio_V=g(-12)+(1-g(-12))*u`, `Noise_V=1+(g(-60)-1)*powf(clamp(q/.8,0,1),float(1/3))`; `g(d)=powf(10,clamp(d,-60,60)*float(.05))`. Это сокращённые выражения F32/CRT, а не обещание bit-exact результата другого языка. Generator/Bus volume port **умножает** базовый scale, Filter Wet/Volume port **заменяет** соответствующее значение. Порядок FX → bus gain → parent mix подтверждён sample kernels. Шум синтезируется локально, его PCM не приходит по сети. Полные пределы и native адреса: [selected operations](<C:/Users/Ded/Documents/Projects/ARMA 3 Scripts/Cellular System/output/von-re-20261104/audio/OPERATION_CHECKLIST.md>).

Важны две границы: **q=0 не означает тишину/запрет доставки**; для deny нужен действительный radio route gate либо отдельный radio-only gain gate. И событие **VON_RADIO включает одновременно Direct и Radio shaders** (`von.acp:325–344`), а VON_DIRECT — Direct shader. Изменение только названных q controls влияет на radio подграф. Остановка/приглушение всего VON_RADIO события может убрать и прямую акустическую составляющую. Один network record не означает один render path. Ссылки: [установленный ACP](<C:/Users/Ded/Documents/Projects/ARMA 3 Scripts/Cellular System/output/von-re-20261104/audio/resources/von.acp:325>), [официальный VoN ACP contract](https://community.bistudio.com/wiki/Arma_Reforger%3AAudio%3A_Voice_over_Network). Требуемые имена событий и Stream `"Stream"` следует сохранить.

## Один минимальный будущий capability test: custom signal binding

**Сейчас NOT_RUN; это план отдельного разрешённого SDK/runtime этапа, не продуктовый код и не acceptance всего RICON.** Тест решает ровно один вопрос: читает ли native VoN ACP arbitrary signal с source proxy, сохраняя независимость source/listener. Carrier production-trust отдельно остаётся в области radio.

1. В изолированном тестовом addon создать собственные копии ACP/SIG, сохранить hardcoded event/Stream names и всю native voice цепочку. Добавить один Input `RICON_DSPProbe` с неглобальной entity областью. Только конечный radio bus gain получает дополнительный множитель этого Input; общий voice bus и Direct shader не меняются. Это делает probe0 тишиной radio, probe1 baseline; штатное q оставить фиксированным хорошим. Подготовка тестовых assets/compile — отдельный будущий этап.
2. Использовать A,B,C: B принимает A и C на одном RX; C принимает A. Для измерения radio A/C сначала вне direct-range B. На B через обычные local signals создать `RICON_DSPProbe` на source A-proxy и C-proxy; на C — на source A-proxy. Начальные значения1. Контрольная запись на receiver B entity имеет отличное sentinel значение и не должна управлять всеми источниками. Индекс хранить вместе с конкретным SignalsManager/lifetime; не переносить на новый actor.
3. При уже идущем **том же native A→B voice** переключить только A-proxy у B `1 → 0 → 1`, без retune, пересоздания ACP или запуска второго PlayEvent. Сохранить фактический выходной аудио результат: A radio у B исчезает/возвращается; C radio у B и A radio у C неизменны. Логи `SetSignalValue`, чтение manager и OnReceive q — вспомогательные receipts, не PASS. Проверить также изменение receiver-entity sentinel: оно не должно подменять source-specific результат.
4. Переместить A в direct слышимость B и повторить только probe0/1: A Direct→B остаётся слышимым до/во время/после, C→B и A→C сохранены. Затем один respawn/rebind A: старый manager/index/generation не меняет новый поток, новая local registration восстанавливает управление; при missing actor результат обозначается недоступным, без выдуманного fail-closed native gate.

**PASS:** фактическая непрерывная native voice на выбранном radio render path реагирует на source-local probe у нужного listener, другие две пары и Direct сохраняются; current instance не подменялся собственным WAV/event, stale generation не действует. **FAIL:** реагирует только SoundComponent-пример, все источники/Direct меняются вместе, нет реакции native VoN, нужен private pointer или эффект появляется только после recreating event. При отсутствии измерения результата — INCONCLUSIVE, а не PASS. Даже PASS квалифицирует client radio DSP bridge; он сам по себе не фильтрует серверную packet delivery и не защищает от модифицированного клиента.
