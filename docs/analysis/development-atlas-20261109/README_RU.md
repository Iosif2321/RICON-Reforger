# RICON → RICON REFORGER: полное дерево разработки

Откройте **RICON_FULL_DEVELOPMENT_GRAPH.html** обычным браузером. Это автономный HTML: установка, сервер, интернет и авторизация не нужны. Файлы `RICON_RADIAL_OVERVIEW.html` и `RICON_FULL_DEVELOPMENT_TREE_RU.md` должны лежать рядом, чтобы работали переходы между представлениями. Ссылки на исходники рассчитаны на исходный локальный workspace.

Карта содержит **186 узлов, 172 листа, 338 зависимостей и 12 больших областей**. Включены legacy RICON/Arma 3, clean-room переход, Core, физика мира, штатный VoN, временные контракты/RECEIVER/SERVER, устройства, инфраструктура M1, multiplayer, радиорелиз, сотовая сеть M3 и расширения M2/финальная приёмка. Порядок обзорных групп служит навигацией; точная очередность задаётся зависимостями. Control plane M3a допускает статическую параллельную работу, когда voice actuator ещё открыт.

Это **карта существующей программы и её доказательств на 9 ноября 2026 года**, а не второй утверждённый roadmap, новый допуск к native-действиям или заявление о готовности мода. Исходные планы и работающая DSH-сессия не менялись. Позднейший прогресс сессии не обновляет этот файл автоматически.

## Как читать и управлять

- **Вы здесь** показывает текущие работы; начальная карточка — ближайшая подготовка native-проверки.
- **Всё дерево** раскрывает все 186 узлов. Колесо меняет масштаб, пустое поле можно перетаскивать. **Читать 1:1** приближает выбранный узел.
- Левая панель ведёт к 12 областям; **+ / −** на карточках раскрывает и сворачивает ветви.
- Поиск находит также закрытые ветви. Четыре фильтра можно сочетать.
- Клик или Enter открывает карточку с критерием готовности, источниками, предшественниками и следующими работами. Пробел раскрывает ветвь; Escape закрывает карточку.
- Пункт **Все 21 раздел плана** связывает требования с узлами. В JSON также сохранены все этапы 0–8, 22 requirements и 14 invariants.

Четыре независимые оси:

| Ось | Значение |
|---|---|
| Работа | Выполнено в своём scope / сейчас / частично / план / блокер |
| Решение | Утверждено / идея / не определено / архивный вариант |
| Доказательство | Source-документ / compile / unit-модель-WB / runtime metadata-callback / audio-content / не проверено / неизвестно |
| Важность проблемы | P0 красный — критично; P1 оранжевый — высоко; P2 жёлтый — средне; P3 синий — низко; серый — без отдельно отмеченной проблемы |

Зелёный статус ограниченного source или модельного результата не подтверждает рабочий Radio/DSP, содержание, сохранность DIRECT или готовность родителя. Число узлов и закрытых пунктов не является процентом готовности продукта. Утверждённая сотовая программа не означает готовую реализацию звонков или выбранную голосовую технику H6.

## Представления и источники

- `RICON_FULL_DEVELOPMENT_GRAPH.html` — основное полное интерактивное дерево с фильтрами.
- `RICON_FULL_DEVELOPMENT_GRAPH.json` — полная семантическая модель, зависимости, coverage и pins.
- `RICON_FULL_DEVELOPMENT_TREE_RU.md` — полное текстовое дерево с критериями и ссылками.
- `RICON_RADIAL_OVERVIEW.html` — радиальный обзор 12 областей с 85 подробными панелями; приближайте или открывайте карточки. Это обзор, не замена полного дерева.
- `RICON_RADIAL_OVERVIEW.svg` — тот же обзор в векторном формате.

Источники: полные canonical Goal и native PLAN (21 раздел / 0–8), общие PLAN v5 / ROADMAP / STATUS, исходный RICON, текущие Core sources/requirements, принятые native evidence и сохранённый ограниченный process snapshot. Documentation, Core mapper и Native mapper подготовили отдельные инвентари; независимый reviewer проверил итоговую модель и renderer. Сотовая часть подтверждается M3a/M3b и ответами владельца; data/billing и полный GSM/LTE/5G stack не добавлены в обязательный scope.

Важные явные границы: A — достаточная доставка содержания и B — адресный Radio-only actuator остаются открытыми. Current owning type/C0 cell не объявлены установленными по source-provenance study. Материалы, RF/RX, CT10, shared RX, parity двух режимов, native/audio/lifecycle/load требуют собственной приёмки. Старые 30/60 и действующие 32 пользователя отражают разные версии нагрузочных сценариев.

## Проверка карты

Сохранён независимый `ACCEPT_FULL_DEVELOPMENT_GRAPH_SOURCE` в `review/REVIEW.json`. Browser checks основного дерева, компактного окна и радиальных карточек находятся в `browser-checks.json`, `compact-check.json`, `radial-browser-checks.json`; итоговые pins и воспроизводимость — в `validation-result.json`. Пакетный генератор радиального атласа прошёл 6 проверок, включая browser self-test. Исторические игровые и численные проверки проекта при создании карты заново не запускались.

Рабочая папка подготовки: `Cellular System/output/ricon-full-development-graph-20261109`. `build.mjs` собирает модель из трёх frozen inventories и создаёт оба представления. Перед будущей пересборкой нужно заново проверить изменения источников и пересмотреть статусы; запуск генератора сам по себе не обновляет смысл прежних доказательств.
